doc_apply_named_style           把命名样式应用到已有段落（DOC）。支持 paragraph_ids（推荐）或 ranges 定位。应用样式时先清除段落直接格式（run 属性 + 段落覆盖），再设 pStyle，确保样式真正生效（不被 run 直设格式覆盖，文档大纲/导航窗格能正确显示层级）。named_style_type 取值：TITLE / SUBTITLE / HEADING_1 ~ HEADING_9 / NORMAL_TEXT。paragraph_ids 直接用 doc_insert_paragraph_with_text 回包的 paragraph_id；ranges 用 doc_resolve_document_structure 的段落 range。两者二选一，paragraph_ids 优先。【示例】{"paragraph_ids":["0F7A3331"],"named_style_type":"HEADING_1"}
doc_clear_format                一键清除指定范围内所有直设格式（DOC），重置为继承样式。同时清除 Run 层（加粗/斜体/下划线/删除线/字号/字体/颜色/高亮/上下标等）和段落层（对齐/缩进/间距/标题级别/边框等）的直设格式。
doc_compare_documents           对比两个已打开的 DOC 文档的内容和格式差异。返回段落级别的差异列表，包括新增/删除/内容修改/格式修改。两个文档必须都已通过 open_file 打开。当前文档作为基准（source），通过 other_file_id 指定对比目标（target）。差异类型：added（目标新增）、deleted（源文档删除）、modified_content（内容变化）、modified_format（格式变化，如对齐方式、标题级别、段落样式等）。还支持对比页眉页脚、文本框（textbox/代码块/高亮块）、表格、批注和页面设置（页边距/页面尺寸）的差异。文本框对比：返回 textbox_diffs 字段，每项包含 type（code_block/highlight_block/textbox）标识类型，即使两个文档中同一位置的代码块 placeholder ID 不同也能按位置匹配识别为同一个代码块的内容修改。表格以原子单元对比：返回 table_diffs 字段，diff_type 包括 added/deleted/modified（维度不同）/modified_content（维度相同但单元格内容不同）/modified_format（维度和内容相同但单元格格式不同，如背景色）。cell_diffs 列出具体差异的单元格坐标（1-based），每个 cell diff 包含 diff_type（modified_content/modified_format）、source_text/target_text（内容差异时）、source_fill_color/target_fill_color（格式差异时，hex 颜色值）。用户可进一步调用 resolve_document_structure 获取表格内部详细结构。性能优化：当一篇文档正文明显更长时，长文档尾部段落不逐段对比。页眉页脚、文本框、批注始终完整对比，不受正文截断影响。
doc_copy_format                 格式刷（DOC）：将源范围的段落属性和文本属性复制到目标范围。读取 source_range 起始位置处生效的段落格式（对齐、缩进、间距、样式等）和文本格式（加粗、斜体、字号、字体、颜色等），然后应用到 target_ranges 指定的所有范围上。适用于快速统一多个段落/文本的格式。
doc_delete_comment              删除单条批注（DOC）。`id` 来自 doc_get_comments 返回的批注 id。若同一锚点仍有其他批注或回复，只删除指定批注正文并保留锚点；若这是该锚点的最后一条批注，则同时移除对应的 commentRange/Reference。不会删除被批注的文档正文。删除会改变 DOC 坐标，后续操作请重新获取位置。
doc_delete_paragraph            删除 idx 所在的整个段落（DOC）。只需要传光标所在位置 idx；底层会自动定位该段落的完整范围并删除，包含该段落结束符。idx 必须是 DOC 坐标；不要传 paragraph_index 或手算字符数。删多段须从后往前逐次调用并重新查询 idx；不可删除主文档最后一个段落。
doc_delete_table                删除整张表格（DOC）。优先使用 table_id 定位（8字符稳定标识），未提供 table_id 时使用 idx（表格内任意 cell 的 GCP 坐标）。删除后表格后面的内容位置会发生偏移，请谨慎使用删除工具，需要先获取用户确认再使用。
doc_delete_table_column         删除表格中的一列（DOC）。通过 table_id 或 idx 定位表格（优先 table_id），col 为 1-based 列号。如果删除所有列则整个表格被删除。
doc_delete_table_row            删除表格中的一行（DOC）。通过 table_id 或 idx 定位表格（优先 table_id），row 为 1-based 行号。如果该行包含 vMerge 合并单元格会自动处理。如果删除所有行则整个表格被删除。
doc_find                        查找文本所在位置（DOC），返回所有匹配位置的 begin/end 索引、上下文及定位锚点。返回的 begin/end 是可直接回填到 doc_replace_text / doc_update_text_property 的 DOC 坐标；不要按肉眼字符数、段落序号或行号手算位置。每个匹配额外返回：related_text（前后各30字上下文，[匹配文本]标记位置）、paragraph_id（可直接传给 doc_modify_paragraph(paragraph_id=)）、table_id/table_index/row/col（匹配在表格内时返回，可直接定位到单元格）。
doc_find_and_replace            查找并替换文本（DOC）。可通过 scope 限定替换范围。
doc_find_and_set                按文本内容 + 文本属性组合查找，对匹配项批量执行替换/改属性/删除（DOC）。
doc_get_comments                获取 DOC 文档中所有批注（DOC）。返回 `total` 与按 range_begin 升序排列的 `comments` 数组，每条包含：`id`（批注 id，与 doc_insert_comment 写入时一致）、`range_begin` / `range_end`（批注锚定范围的字符 idx，与 doc_get_last_operable_pos.position 同坐标系；begin == end 表示零长度的「点锚」批注，对应字段 `is_point_anchor=true`）、`text`（批注正文文本，已过滤其中的图片/表格等复杂内容，与 OOXML 视觉渲染对齐）、`reply_to`（同一对话线程首条批注的 id，仅回复批注才有；底层线程为扁平结构）、`author` / `date`（作者展示名与 Unix epoch 毫秒时间戳字符串，未设置时不返回）。主要用于对 doc_insert_comment 的结果做验证、以及在执行批注相关编辑前枚举现有批注。
doc_get_images                  获取 DOC 文档中所有图片的信息（DOC）。返回数组中每一项包含以下字段：`source` (1 = drawing 嵌入图片，2 = field-attachment 字段附件图片)、`index` (图片在文档中的字符 idx，与 doc_insert_image / doc_replace_image 的 index 、doc_get_last_operable_pos.position 同一坐标系)、`image_url` (本会话的可寻址 URL，doc_replace_image 可拿来作为 old_image_url 使用)。数组按 index 升序返回；“第 N 张图”即为数组下标 +1，无需额外字段。
doc_get_last_operable_pos       获取DOC文档正文最后一个可操作位置的索引，以及该位置前面最多10个字符的内容。在需要向文档末尾追加内容时，可先调用此接口获取末尾可操作位置（DOC）。返回的 position 是可直接传给插入类工具的 DOC 坐标，不是可见字符序号。
doc_get_outline                 获取文档大纲树（DOC）。只返回标题层级结构（Heading 1-9），不包含表格/图片/普通段落等非标题节点。返回树形结构，每项含 title / level / title_start / title_end / content_start / content_end。适用场景：快速了解文档章节结构和定位插入位置。如需获取完整文档结构（含表格 cells、段落、图片等），请用 doc_resolve_document_structure。
doc_get_paragraph_property      读取 DOC 文档指定位置 idx 所在「段落」的属性（与 doc_insert_paragraph 字段对称）：段落样式名（可读，如 heading 1 / Title / Normal）、大纲级别、推断出的 heading_level (1..9, 0=非标题)、是否带编号及编号级别 (1..9)、对齐方式、缩进（pt）、段前/后间距 (pt) 与行距。字段不存在表示未显式设置（继承默认值）。同时回读分页控制（keep_with_next/keep_together/page_break_before/widow_control）、自定义 tab_stops，以及 numbering_restart（当前 num_id 首段=true，续接=false）。主要用于对段落编辑结果做验证。
doc_get_section_property        读取 DOC 文档指定 section 的基础页面属性。section_index 为 0-based，与页眉页脚接口一致。返回 section 范围、总节数、页面方向和宽高、页边距、页眉页脚距离、装订线、分节起始类型以及是否首页页眉页脚不同。所有长度统一为 pt。
doc_get_table_info              获取指定表格的完整信息（DOC）。定位方式三选一（优先级 table_id > idx > table_locate）：① table_id（8 字符稳定标识，取自 doc_list_tables，最推荐）；② idx（表格内任意 GCP）；③ table_locate.cell_match（按单元格文字定位）。手上都没有时先 doc_list_tables 拿 table_id。
doc_get_text_property           读取 DOC 文档指定位置 idx 处生效的文本属性（与 doc_update_text_property 字段对称）：加粗/斜体/下划线及线型/下划线颜色/单删除线/双删除线/小型大写/颜色/底纹(background_color)/高亮(highlight)/字号(pt)/字体/上下标等。响应中「字段不存在」表示该属性未在 run 上显式设置，应认为「继承自段落 / 样式默认值」。
doc_get_word_art_info           读取指定位置艺术字的属性。返回字段：wordart_idx（锚点位置）、style（视觉效果名）、text（艺术字文字）、width_px / height_px（外框尺寸）、text_range: {begin, end}（艺术字文字的 GCP range，可传给 doc_update_text_property.ranges 修改字号/颜色/字体等；空框艺术字不返回此字段）。
doc_insert_border               在指定位置插入分隔符（DOC）。通过设置段落底部边框来实现水平分隔线效果。⚠️ idx 必须是「分隔线上方那个段落」的 end_index（即该段落的段落分隔符 ¶ 的位置）。例如：想在第 2 段和第 3 段之间插入分隔线，应传第 2 段的 end_index。idx 是 DOC 坐标，不要按肉眼字符数或段落序号手算。支持多种边框样式（single/thick/dotted/dashed等）和自定义颜色。
doc_insert_comment              插入批注（DOC）。接口返回中除 last_edit_index 外，还会多带一个 `position` 字段（插入后文档末尾可操作位置），避免调用方为了拿插入后的位置再去调 doc_get_last_operable_pos。说明：批注插入会为文档插入 commentRangeStart/End/Reference 等占位符，文档总长度会增加；后续操作请以 `position` 为准。
doc_insert_footer               设置页脚文本内容（DOC）。覆盖式写入：先清空已有页脚内容，再写入新文本。本工具一次只处理一个 section（由 section_index 指定）；如需对多个 section 都写入页脚，请按需多次调用本工具。首次插入时会为目标 section 独立创建页眉页脚 substory，打破该 section 与前一节"链接到上一节"的关系。
doc_insert_footnote             在指定位置插入脚注或尾注（DOC）。脚注显示在页面底部，尾注显示在文档末尾。idx 是 DOC 坐标，不要按肉眼字符数或段落序号手算。⚠️ idx 应该使用目标文本的最后一个字符位置（即段落的 end_index - 1，段落分隔符 ¶ 之前），这样脚注/尾注引用标记会出现在文本末尾而非中间。
doc_insert_header               设置页眉文本内容（DOC）。覆盖式写入：先清空已有页眉内容，再写入新文本。本工具一次只处理一个 section（由 section_index 指定）；如需对多个 section 都写入页眉，请按需多次调用本工具。首次插入时会为目标 section 独立创建页眉页脚 substory，打破该 section 与前一节"链接到上一节"的关系。
doc_insert_html_content         在指定 idx 处插入一段 HTML 富文本（DOC），引擎会按 HTML 标签 / 内联样式自动转为段落、标题、列表、表格、链接、加粗 / 斜体 / 下划线、文字色 / 背景色等富文本元素。本接口为批量解析模式，一次调用可插入多个段落 / 列表 / 表格。
doc_insert_image                在指定位置插入图片（DOC）。**优先使用 image_path 传本地图片文件的绝对路径**（image file local path；Windows 如 C:\Users\me\a.png，POSIX 如 /home/me/a.png）；这是最省 token、最不易出错的方式。仅当图片确实只存在于内存、没有落盘文件时，才用 content 传 data URI（该形态仍完全支持）。image_path 与 content 二者必填其一（同时传以 image_path 为准）。不支持纯 base64 字符串（请加 data: 前缀），也不支持 http(s) 远程 URL。插入成功后直接返回新图的 image_url，无需再调 doc_get_images 反查。idx 是 DOC 坐标，需来自查询结果或上一次写操作返回值，不要按肉眼位置手算。
doc_insert_markdown             在指定位置插入 Markdown 格式内容（DOC），支持标题、列表、表格、链接、加粗 / 斜体等常见语法，引擎会自动将 Markdown 转换为文档富文本格式。一次调用可插入多个段落 / 列表 / 表格。
doc_insert_math                 在指定位置插入数学公式（DOC）。C++ 层将 LaTeX 解析为 OOXML OMML 后展开为完整公式：如 "\\frac{1}{2}"、"x^{2}"、"\\sqrt{x+1}"、"\\sum_{i=1}^{n} i" 等。
doc_insert_normal_link          插入普通链接（DOC）。这是在 idx 位置插入一个链接字段，不是给已有文本范围设置链接；显示文本由 text/file_name 决定。idx 是 DOC 坐标，使用查询结果或写操作返回值，不要手算。
doc_insert_page_break           在指定位置插入分页符（DOC）。idx 是 DOC 坐标，使用查询结果或写操作返回值，不是段落序号。
doc_insert_paragraph            在指定 idx 处插入一个「段落分隔符」（paragraph break），并对「该分隔符之前的文本」应用段落级样式。⚠️ 本接口不写入任何文本内容，仅修饰段落属性。⚠️ 这是拆分当前段落的底层接口：idx 之后的段落会保留原段落属性。在编号段末尾调用会得到一个继续编号的空段；不要用本接口创建独立的普通空段，应使用 `doc_insert_paragraph_with_text(idx=段落end_index, text="", type=0)`。
doc_insert_paragraph_with_text  一步插入「带文本的段落」（DOC），新增段落继承上一段属性。在 idx 指定的段落之后插入一个新段落，包含指定的文本和段落属性。推荐调用方首选此接口而非「doc_insert_text + doc_insert_paragraph」两步调用，该接口避免两步之间的位置漂移。
doc_insert_section_break        在指定 DOC/UTF-16 坐标插入分节符。idx 之前的内容保留在前一节，idx 及其后的内容进入后一节；拆分后的前后两节完整继承原节的节级属性，仅后一节的起始类型改为 start_type。段中/段尾插入时，分节前的内容保留原段落属性；段首插入使用干净的结构承载段。不会额外插入段落回车。start_type 可选，默认 new_page。插入后文档坐标和节索引会变化，继续操作前应重新查询。
doc_insert_table                在指定位置插入一张空表格（DOC）。返回值含 `table_info`（格式同 doc_get_table_info 的 `block`），其中 `table_info.id` 即 table_id，直接传给后续表格工具。插入后用 doc_set_table_properties 设属性，用 doc_set_table_cells 填内容。
doc_insert_table_cols           批量在表格不同位置插入多列（DOC）。通过 table_id 或 idx 定位表格（优先 table_id）。所有 anchor_col 基于**原始表格**（调用前的状态），调用方不需要跟踪插入后的列号漂移。handler 内部按 anchor_col 降序处理（先插右边的再插左边的），保证互不干扰。可选 cells 数组为新增列写入内容，用 (insert_index, col_offset, row) 定位，不依赖最终列号。每个插入点可设置 default_cell_format 作为默认样式，cells 中未指定的字段继承默认值，减少 token 消耗。
doc_insert_table_column         在表格中插入一列（DOC）。table_id 或 idx 定位表格（优先 table_id），col 为 1-based 列号（指定从哪列克隆样式），inserted_back 控制在前方/后方插入。插入后自动调整列宽。可选 cells 数组一次完成插列+填内容，不必再调 doc_set_table_cells。
doc_insert_table_row            在表格中插入一行（DOC）。table_id 或 idx 定位表格（优先 table_id），row 为 1-based 行号（指定从哪行克隆样式），insert_below 控制在上方/下方插入。新行克隆源行的 trPr 和每个 cell 的 tcPr/段落/文本属性。可选 cells 数组一次完成插行+填内容，不必再调 doc_set_table_cells。
doc_insert_table_rows           批量在表格不同位置插入多行（DOC）。通过 table_id 或 idx 定位表格（优先 table_id）。所有 anchor_row 基于**原始表格**（调用前的状态），调用方不需要跟踪插入后的行号漂移。handler 内部按 anchor_row 降序处理（先插下面的再插上面的），保证互不干扰。可选 cells 数组为新增行写入内容，用 (insert_index, row_offset, col) 定位，不依赖最终行号。每个插入点可设置 default_cell_format 作为默认样式，cells 中未指定的字段继承默认值，减少 token 消耗。
doc_insert_text                 在指定位置插入文本（DOC）。idx 是 DOC 坐标，必须来自查询结果或上一次写操作返回值；不要按肉眼字符数、段落序号或行号手算。注意：如果需要插入换行，应该要插入段落，而不是在文本里插入换行符号。
doc_insert_toc                  在指定位置插入目录（TOC）。自动收集文档中的标题段落（Heading 1-9），生成带页码引用和超链接的目录。插入前请确保文档已有标题段落（用 doc_insert_paragraph_with_text level=1~9 或 doc_apply_named_style HEADING_1~9）。idx 为 GCP 插入位置（-1=文档开头，链式追加用上次回包 end_index+1）。max_level 收集的最大标题级别（1-9，默认 3，即 H1~H3）。【示例】{"idx":-1,"max_level":3}
doc_insert_word_art             在指定位置插入一段艺术字（带变形样式的文本），返回 wordart_idx 用于后续读/改属性。
doc_list_recent_ai_edits        列出文档最近通过 MCP 写工具产生的 AI 编辑记录（DOC）。
doc_list_tables                 列出文档中所有表格的摘要信息（DOC）。操作表格前优先用本工具拿 table_id（比 doc_resolve_document_structure 更精准、token 消耗更低）。需要完整 cell 内容时调 doc_get_table_info；需要文档整体布局时调 doc_resolve_document_structure。
doc_merge_table_cells           合并表格单元格（DOC）。将 (row, col) 起始的 row_span×col_span 矩形区域合并为一个单元格。通过 table_id 或 idx 定位表格（优先 table_id）。row/col 为 1-based（与 doc_get_table_info 返回的 row/col 一致，直接传入即可）。合并后所有被合并单元格的文本会拼接到起始单元格中。row_span=1 且 col_span>1 为横向合并；row_span>1 且 col_span=1 为纵向合并；两者均>1 为混合合并。
doc_modify_paragraph            修改已有段落的属性（DOC），支持对齐、间距、精确缩进、任意段落样式、分页控制、制表位、引用与编号。本工具用于在原有段落上修改属性，如需添加新的待办事项内容请使用 insert_tasks_with_content，如需添加新的列表项目请使用 doc_insert_paragraph。paragraph_id 与 ranges 至少传一个；paragraph_id 来自 doc_resolve_document_structure。paragraph_id 只保证在当前打开的 editor 实例内用于定位，不保证保存后或重新打开文档仍保持不变。一旦传入 paragraph_id，将按 ID 精确定位唯一段落并忽略 ranges；找不到或重复会报错。未传 paragraph_id 时，ranges 为段落范围列表，每项包含 begin 和 end（DOC 坐标）。坐标必须是当前文档版本的 GCP：每次写文档内容后后续段落坐标会漂移，批量修改前请重新 doc_resolve_document_structure / doc_get_document_content 取最新 start_index/end_index。除定位参数外，至少传入一个需要修改的属性或操作；未传入的属性保持原样。不要传 paragraph_index 或手算字符数。【互斥】indent / block_quote / numbering / highlight_block 四者互斥；且均不能与 jc、spacing_*、line_spacing*、heading_lvl 同包（会报错，不会静默忽略）。需要「编号 + 间距/对齐」等组合时，分多次调用，每次只带一类属性。【示例·接编号】ranges 取 doc_resolve_document_structure 该段 start_index/end_index：{"ranges":[{"begin":675,"end":705}],"numbering":"decimal","numbering_level":1}【示例·再改间距】第二次调用，勿与 numbering 同包：{"ranges":[{"begin":675,"end":705}],"spacing_before":7.8,"spacing_after":7.8}【示例·对齐+行距】jc/spacing/line_spacing/heading_lvl 可同包：{"ranges":[{"begin":0,"end":15}],"jc":"center","line_spacing":1.5,"line_spacing_rule":1}
doc_modify_section              修改 DOC 文档指定 section 的基础页面属性。section_index 为 0-based；未传字段保持不变，传 null 删除该直接设置并恢复 OOXML 默认。所有长度统一为 pt。orientation 单独设置时会自动交换现有页面宽高，使 portrait/landscape 立即生效；若同时传 page_width/page_height，则以显式尺寸为准。
doc_replace_image               替换文档中已有图片为新图片（DOC）。必须同时传入 idx 和 old_image_url（均取自 doc_get_images 的返回值），二者缺一会返回参数错误。**新图优先用 new_image_path 传本地图片文件的绝对路径**（image file local path）；仅当图片只存在于内存、没有落盘文件时才用 new_content 传 data URI（该形态仍完全支持）。new_image_path 与 new_content 二者必填其一（同时传以 new_image_path 为准）。替换成功后直接返回新图的 image_url，无需再调 doc_get_images 反查。
doc_replace_text                替换 range 范围内的文本为指定文本（DOC）。begin/end 是 DOC 坐标，直接使用 doc_find 返回的 begin/end，不要手算。
doc_resolve_document_structure  获取文档结构树（DOC），返回扁平节点列表，用于在调用需要 idx/index/ranges 的写类工具前定位位置。DOC 的 idx/begin/end 是 UTF-16 code unit 坐标，包含段落结束符、表格、图片、字段等结构占位；不要按肉眼字符数、段落序号或行号手算。节点 type：Paragraph / Heading（heading_level 1..9）/ Title / Subtitle / Table；编号段的 numbering_type 与写接口一致，可为 bullet / decimal_comma / task / decimal / bullet_arrow / bullet_hollow_circle / multilevel_decimal / chinese_numbering / upper_letter；文字下划线/删除线/高亮通过 has_highlights 标志位 + highlight_spans 嵌入在 Paragraph 内.
doc_set_block_quote             设置或取消段落引用（DOC）。通过 paragraph_ids 定位目标段落，paragraph_id 的解析在服务端内部完成，调用方无需感知 GCP 坐标。paragraph_ids 直接用 doc_insert_paragraph_with_text 回包的 paragraph_id（插入即返回），或 doc_resolve_document_structure 的 paragraph_id 字段。引用块是段落级属性（左侧蓝色竖线 + block_quote 标记），每段独立设置，不合并区间。enable=true 设置引用，enable=false 取消引用。【示例】{"paragraph_ids":["0F7A3331","0F7A3332"],"enable":true}
doc_set_document_style          设置文档级默认样式（DOC），一次调用修改文档基底格式。包括三部分（均可选，只传需改部分）：
doc_set_highlight_block         把已有段落设置为一个高亮块（DOC）。通过 paragraph_ids 定位目标段落，paragraph_id 的解析在服务端内部完成，调用方无需感知 GCP 坐标（不会因坐标漂移出错）。paragraph_ids 直接用 doc_insert_paragraph_with_text 回包的 paragraph_id（插入即返回，无需再调 doc_resolve_document_structure）；查历史段落时也可用 doc_resolve_document_structure 的 paragraph_id 字段。高亮块是段落级属性：每个 paragraph_id 对应一个独立的高亮块（一段一个 textbox 容器），不合并区间。多段场景服务端循环逐段转换，每段独立保留自身样式/缩进。对比 doc_modify_paragraph.highlight_block：后者按 GCP ranges 定位且一次只处理第一个 range，本工具按 paragraph_id 定位且天然支持多段（各段独立高亮块）。【示例】{"paragraph_ids":["0F7A3331","0F7A3332"],"bg_color":"FEF8E4","border_color":"FBEBAE"}
doc_set_page_number             设置页码（在页脚中插入 PAGE 字段）（DOC）。默认参数组合：页面底部右侧 + 1,2,3 格式 + 续前节 + 应用于整篇文档。调用前会自动切换为分页模式。position / format / continue_from_prev 均已支持；scope 目前仅支持 whole_doc，传入 from_here / current_section 会走空路径，不产生任何修订。
doc_set_table_cells             批量设置表格单元格内容与样式（DOC）。凡涉及表格单元格的文本/格式/属性/对齐/超链接/图片修改，都必须用本工具（禁止用 GCP 坐标类工具改表格）。table_id 或 idx 定位表格（优先 table_id），row/col 为 1-based。text 整体替换单元格文本；property 改底色/垂直对齐/边框；text_format 改字体格式；horizontal_align 改段落对齐。多 cell 共用样式时提到 common_cell_properties，cells 只写差异（inherit:false 可跳过公共样式）。合并单元格：mc=true 格自动定位到合并起始格应用格式，文本替换仅对起始格生效。
doc_set_table_properties        修改表格属性 + 布局（DOC）。通过 table_id 或 idx 定位表格，优先使用 table_id（8字符稳定标识，不随编辑漂移）；未提供 table_id 时使用 idx（表格内任意 cell 的 GCP 坐标）。可同时设置边框、对齐、宽度、单元格内边距、条件染色、垂直对齐、行高、列宽。全部字段可选，未提供的属性沿用原表格设置。
doc_to_image                    将本地 DOC/DOCX 文档渲染为逐页图片（PNG）。流程：获取临时上传凭证 → 上传本地文件到 COS → 调用 slidetools /api/v6/slidetools/convert/doc_to_images 完成转换 → 把每页图片下载到本地目录。输入为 docx 文件的绝对路径（不需要先 open_file），返回每页图片的本地绝对路径与页数。无需登录态。适用于需要预览文档页面 / 做 OCR / 生成缩略图的场景（DOC）。如果 AI 需要查看编辑完文档后的视觉效果，可以调用该工具将文档转为图片进行确认。但不建议每次调用完编辑工具就立即转图查看，而是在单个会话的编辑任务全部完成之后，再统一调用一次转图查看最终效果，以避免不必要的性能开销。
doc_undo_ai_edit                撤销指定 version 的 AI 编辑（DOC）。
doc_unmerge_table_cells         拆分表格单元格（DOC）。将 (row, col) 处的已合并单元格拆分为 row_num×col_num 个单元格。通过 table_id 或 idx 定位表格（优先 table_id）。row/col 为 1-based（与 doc_get_table_info 返回的 row/col 一致，直接传入即可）。row_num/col_num 为拆分后的目标行数/列数（≥1，=1 表示该方向不拆分）。如果单元格未合并（grid_span=1 且 v_merge 无），仍会按参数插入新单元格。
doc_update_named_style          修改命名样式的定义（DOC），一次调用立即影响文档中所有使用该样式的段落。例如：修改 HEADING_1 的 font_size 为 18，所有 H1 段落字号都变为 18pt。不需要逐段修改，不需要先查结构再遍历——直接指定样式名和新属性即可。支持的 named_style_type：NORMAL_TEXT, HEADING_1~HEADING_9, TITLE, SUBTITLE。也可传文档内实际的 styleId 字符串（如从 doc_resolve_document_structure 获取的 style_id）。paragraph_style 和 text_style 至少传一个；只传需要修改的子字段。【示例·所有H1改为16pt居中】{"named_style_type":"HEADING_1","paragraph_style":{"jc":"center"},"text_style":{"font_size":16}}【示例·正文行距改1.5倍】{"named_style_type":"NORMAL_TEXT","paragraph_style":{"line_spacing":1.5,"line_spacing_rule":1}}
doc_update_text_property        更新指定字符范围内的文本属性（DOC）。仅修改样式，不改变文档内容长度，因此返回值不包含 position 字段（与其他 insert_* 接口不同）。支持加粗、斜体、下划线（含线型/颜色）、单删除线、双删除线、小型大写、文字色、底纹色、高亮、字号、字体、上下标，所有样式字段均为可选，未传的字段保持原样不变。background_color 是底纹颜色，highlight 是高亮文本，二者不同，同时设置时高亮会覆盖底纹。
