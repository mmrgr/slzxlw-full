## 2. 逐条核验结果

### 2.1 大部分经得起检查
例：
- `abstraction never equals delivered: 0 of 68` ✅（已由门禁覆盖）
- `the predictor cannot access x_AI, M_0, ...; we assert this in code` ✅（代码级事实）
- `Water chemistry is a switch, not a modifier` ✅（**带条件**：no quality penalty **and** no surplus，且 80/80 数据支撑）

### 2.2 ★ 发现一处**表述不准确**：`0.000000 ML exactly (80/80)`

主稿表格第 357 行与 SI 第 333 行都写：

> A — pool committed: **0.000000 ML exactly** (80/80)

**实测**（`limit_scale=1e6` 子集，branch-A 纯挤占）：

| 量 | 数量 |
|---|---:|
| n | 80 |
| **严格 `== 0.0`** | **36** |
| `\|dS\| < 1e-12` | 44 |
| `\|dS\| < 1e-11` | **80** |

⇒ **严格等于 0 的只有 36/80**，其余 44 个是 `±1.8e-12 ~ 7.3e-12` 的**浮点残差**。

**说 "0.000000 ML exactly (80/80)" 是错的**——80 个里有 44 个不是恰好零。

### 2.3 修正
改为：
> **0 to machine precision** — residual below $10^{-11}$ ML in all 80/80 cases (36 exactly 0.0)

既说明了结论（机器精度下为零），又如实交代了"严格零只有 36 个"。

## 3. 顺带确认一条"看起来太满"但实际成立的断言

主稿表格：`C — surplus | ≤ 0 always, down to −22,359 ML`

我第一反应是它与 branch-C 的 **11 个 dS>0 例外**矛盾。但查上下文发现：

|---|---|

### 3.1 但仍指出一个可读性风险

## 4. 过程中第 10 次踩到 `\r` 转义坑

修 LaTeX 时用普通字符串写入 `\rm`，导致 `\r` 变成真实换行符 / 回车符，
`$|dS_{\rm pot}|$` 变成 `$|dS_{<LF>m pot}|$`。

**修复过程**：
1. 用 `repr()` 逐字符打印，确认是 **U+000A（LF）**，不是字面 `\n`
2. 用正则 `r'dS_\{\nm pot\}'` 精确替换
3. 再验证全文无 `_{<换行>` / `_{<回车>` 残留

**教训（已第 10 次）：写含反斜杠命令的字符串，必须用原始字符串 `r"..."`。**
