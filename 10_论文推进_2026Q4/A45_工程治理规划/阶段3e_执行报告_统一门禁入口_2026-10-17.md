## 2. ★ 一次 shell 事故（必须记录）

### 2.1 发生了什么
我用 heredoc 往主稿里写这句 Markdown：
```
A single entry point (`A41_全包审计/run_all_gates.py`) runs all eleven…
```
**bash 把反引号里的内容当作命令执行了**，结果主稿里变成：
```
A single entry point () runs all eleven…
```
——**路径被吞掉了**，而且我的 grep 检查因为这个扰动完全没输出。

### 2.2 为什么这是本项目的"老毛病"
这是本项目**第 6 次**被 shell 转义坑：
| 次数 | 触发 | 后果 |
|---|---|---|
| 1 | `\b` | 正则静默失效，返回 0 条却判 PASS |
| 2–3 | `\v` | `\varphi` → 垂直制表符 |
| 4 | `\a` / `\r` | `\approx` / `\rm` 被破坏 |
| 5 | `\r` | 表格替换失败 |
| **6** | **反引号** | **Markdown 路径被 shell 执行并吞掉** |

### 2.3 处置
1. **用脚本文件**（`_lib/fix_eaten_path.py`）写回正确文本，不经 shell；
2. **新增检查**：`structure_gate.py` 增加"无空路径"项，精确匹配 `point ()` 这一损坏形态。

### 2.4 一个自己造成的小坑（也要记录）
第一版检查我写的是 `\(\s*\)`，结果**匹配到空字符串**，在每个位置都命中，
输出刷屏上万行。改为**只匹配 `point ()` 这一具体形态**后正常。

> 教训：正则要"靶向"具体损坏形态，不要写宽泛的"空括号"模式。
