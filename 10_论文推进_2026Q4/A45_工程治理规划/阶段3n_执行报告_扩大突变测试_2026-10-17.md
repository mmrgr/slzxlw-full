## 2. 缺陷一：突变未生效被误判为"门禁有效"

### 2.1 现象
加入"陈旧值黑名单"用例后，突变测试报告"杀死"。
但单独核实发现：**exit=0，门禁根本没失败。**

### 2.2 根因
我的突变函数作用于**主稿**，而目标字符串 `residual (ML, relative)` 在 **SI** 中。
`str.replace` 找不到就返回原文本 —— **突变实际没有发生**。

于是门禁在"无缺陷"的文档上运行，自然通过；而我只看 exit code，误以为它"杀死"了缺陷。

### 2.3 修复（**两处**）
1. 把该用例改为作用于 SI；
2. **给突变框架加硬校验**：
   ```python
   mut = new_text_fn(orig)
   if mut == orig:
       raise RuntimeError(f"突变未生效: {tag} 中未找到目标字符串")
   ```

> **这是本轮最重要的发现**：突变测试本身也会假阳性。
> **若突变没生效，门禁"通过"会被误读成"门禁有效"——方向完全相反。**

## 3. 缺陷二：`投稿声明` 门禁失败时仍返回成功

### 3.1 问题
`A43_投稿声明/required_statements.py` 末尾：

```python
# 主稿缺失这些声明 → 非零退出以提示     ← 注释这么说
print(f"主稿仍缺声明: {missing if missing else '无'}")
sys.exit(0)                              ← 但实际恒为 0
```

**注释与实现相反。** 实证：删掉 `### Data availability` 后，脚本打印
`主稿仍缺声明: ['Data availability']` 但 **exit=0**。

而 `run_all_gates.py` 判定用的是**输出文本**（`r"占位符"` 匹配），
所以门禁"看起来"通过 —— 但只要有人改用退出码，就会漏判。

### 3.2 修复
```python
sys.exit(1 if missing else 0)
```

**验证**：正常 exit=0；注入缺陷后 **exit=1** 并输出缺失项。

## 8. 本轮的方法论收获

### 8.1 突变测试需要"元校验"
如果突变的文本替换没有匹配到目标，测试会**静默地在无缺陷状态下运行门禁**，
产生**假阳性**（门禁看起来通过 → 误判为"它不检查这个"或"它有效"）。

**必须显式断言"突变已发生"。**

### 8.2 注释与实现不一致是常见陷阱
`sys.exit(0)` 旁边写着"非零退出以提示"——这类**注释说谎**比没有注释更危险：
它会让后来者相信功能已实现。

### 8.3 目前发现的"检查自身有问题"清单（累计）
| 轮次 | 问题 |
|---|---|

| 3-l | `form_gate` 里有**恒为空**表达式 |
| 3-m | `hygiene_gate` 只检查 4 种扩展名，漏 39% |
| **3-n** | **突变未生效被误判；`sys.exit(0)` 注释说谎** |

**共性：检查/测试代码自身缺乏验证。** 这是本项目最隐蔽的一类技术债。
