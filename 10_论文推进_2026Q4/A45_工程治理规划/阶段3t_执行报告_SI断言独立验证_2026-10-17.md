## 2. ★ 第一次重算，我算出了 25/39——错的

### 2.1 我的做法
```python
d = pd.read_csv('A15_稳健性/grid_resolution_points.csv')   # 14,196 行
d = d.sort_values(['sample','limit_scale','rho'])
for (sample, limit_scale), g in d.groupby(['sample','limit_scale']):
    feas = g['feasible'].values
    # 找"任意 False 后出现 True"
```
得到 **25/39**，与论文的 11/39 相差很大。

### 2.2 差在哪（两个错误叠加）

| 错误 | 说明 |
|---|---|
| **① 混用网格级别** | 数据含 **4 个网格级别**（n_level = 25 / 49 / 97 / 193）。每个 `(sample, limit_scale)` 组内**混了 4 个层级的行**，拼接后序列是 `[25级…, 49级…, 97级…, 193级…]`，层级交界处产生假性 `False→True`。 |
| **② 定义不同** | 原始脚本用的是"**首个 True 与最后一个 True 之间是否存在 False**"，我用了"**任意 False 后出现 True**"。 |

**这两个错误叠加，得到 25/39。**

### 2.3 正确做法
```python
finest = d[d.n_level == d.n_level.max()]        # 限定最细网格
# 用原始脚本的定义: 首个 True 与末个 True 之间是否有 False
⇒ 11/39 = 28.2%  ✓ 与论文完全一致
```

## 4. 据此改进主稿表述

原文：
> **11 of 39** scanned curves are **non-monotone**

问题：没说清是哪个网格级别。读者若拿别的级别重算，可能得到不同数。

改为：
> **11 of 39** curves are **non-monotone at the finest grid level** — … (the count is
> **10/39 at the coarsest level and 11/39 at every finer level, so it is grid-converged**)

**这比原来更严谨**：既限定了网格级别，又主动给出了收敛证据。
