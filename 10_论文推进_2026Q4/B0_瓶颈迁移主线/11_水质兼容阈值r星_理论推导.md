# 水质兼容阈值 r*：从经验现象到解析判据

**编制日期**：2026-10-18
**性质**：理论推导 + 实证核验。本文件是新一轮工作的核心理论文档。

---

## 0 一句话

> **再生水冷却存在一个可闭式求解的替代率阈值 r\*。当政策目标 r 超过 r\* 时，冷却系统的浓缩倍数被混合水质压破设计值，单位散热所需补水量上升——于是"提高再生水比例"这个节水措施，反而推高取水量。**

这个阈值可以精确算出来，不需要跑模型：

```
r* = (L / CoC_design − C_potable) / (C_reclaimed − C_potable)
```

## 1 上一轮的错误结论（必须撤回）

上一轮（2026-10-18 早些时候）的 `10_文献对标与定位诊断.md` §三候选 1 写道：

> 「在现有模型结构下，CoC 是输入参数而非响应变量，因此水质在整个容量区间内恒定不变（HA 恒 4.322、CO 恒 5.000），物理上不可能成为"首失效约束"。」

**这个结论是错的。** 它基于三个错误的推断：

| 错误 | 实际 |
|---|---|
| 认为 CoC 是常量输入 | `data_center.py:222-258` 的 `_cycles_of_concentration` 明确按 `min(design, limit/C_mix)` 求解，CoC 是 r 的函数 |
| 只在**一个** r 下扫描容量 | 从未遍历 r 维度，所以看到的 4.322 是该 r 下的固定值，被误读为"与 r 无关的常量" |

## 2 推导

### 2.1 补水需求的物理式

蒸发冷却塔的水量平衡（稳态、忽略飘滴）：

```
E = 蒸发量（由排热量决定，与水质无关）
B = 排污量（blowdown）
M = 补水需求（makeup）
CoC = M / B        （浓缩倍数定义）
```

由盐分平衡（盐随补水进、随排污出，蒸发不带盐）：

```
M · C_makeup = B · C_loop
```

结合 `CoC = M/B`：

```
C_loop = CoC · C_makeup
```

冷却塔的**运行约束**是 `C_loop ≤ L`（换热器结垢/腐蚀限值，如 TDS ≤ 2200 mg/L）。故：

```
CoC ≤ L / C_makeup
```

### 2.2 CoC 是 min，不是常量

模型（`data_center.py:251-258`）正是这么实现的：

```python
ratios = [limit / concentrations[indicator] for indicator, limit in limits.items() ...]
return max(1.000001, min(design, min(ratios))), False
```

即：

```
CoC(r) = min( CoC_design, L / C_mix(r) )
```

**两种机制取紧**：
- **设备机制**：换热器/塔体结构决定的设计上限 `CoC_design`（本例 5.0）；
- **水质机制**：盐分平衡决定的 `L / C_mix`。

设计值只在**水质不紧**时才是有效约束。

### 2.3 混合水质

再生水（TDS `C_r`，通常 400–800）与自来水（TDS `C_p`，通常 100–300）按替代率 r 混合：

```
C_mix(r) = r · C_r + (1 − r) · C_p
```

### 2.4 解出 r\*

令水质机制刚好等于设计值：

```
L / C_mix(r*) = CoC_design
⟹ C_mix(r*) = L / CoC_design
⟹ r*·C_r + (1−r*)·C_p = L / CoC_design
⟹ **r* = (L/CoC_design − C_p) / (C_r − C_p)**
```

**物理含义**：`L/CoC_design` 是"设计浓缩倍数下，补水允许的最高含盐量"。若混合补水的含盐量超过它，就无法在设计 CoC 下运行。

### 2.5 两区间的行为

| 区间 | CoC | 补水需求 `M = E·CoC/(CoC−1)` | 政策效果 |
|---|---|---|---|
| `r ≤ r*` | `= CoC_design`（恒定） | 恒定 | 替代**纯收益**：淡水等量下降，总取水不变 |
| `r > r*` | `= L/C_mix(r)`（随 r 下降） | **上升** | 替代**部分被侵蚀**：淡水降，但补水总量涨；净节水打折 |

**r > r\* 时补水需求对 r 的导数**（记 `C(r) = L/(rC_r+(1−r)C_p)`）：

```
dM/dr = E · d/dr [ C/(C−1) ] = E · [−1/(C−1)²] · dC/dr
dC/dr = −L(C_r − C_p)/C_mix²  < 0
⟹ dM/dr = E · L(C_r−C_p) / [ C_mix² (C−1)² ]  > 0
```

**补水需求随 r 单调上升。** 这就是"节水反噬"的解析形式。

### 2.6 反噬强度的解析式

从 `r ≤ r*` 到某个 `r > r*`，补水的相对增幅：

```
ΔM/M = [ C(r)/(C(r)−1) ] / [ CoC_d/(CoC_d−1) ] − 1
```

代入 HA 参数（`L=2200, CoC_d=5, C_p=180, C_r=650, r*=0.5532`）：

| r | CoC | M/E | ΔM/M（相对 r≤r*） |
|---:|---:|---:|---:|
| 0.50 | 5.0000 | 1.25000 | 0.00% |
| 0.5532 | 5.0000 | 1.25000 | 0.00% |
| 0.60 | 4.7619 | 1.26582 | **+1.27%** |
| 0.70 | 4.3222 | 1.30101 | **+4.08%** |
| 0.80 | 3.9568 | 1.33820 | **+7.06%** |
| 0.90 | 3.6484 | 1.37758 | **+10.21%** |

> ⚠ **2026-10-19 审计更正**：本表原有四个 `ΔM/M` 值与上方公式不符
> （旧值 +1.32% / +4.09% / +6.99% / +10.64%，对应 `M/E` 1.26655 / 1.30114 / 1.33733 / 1.38303），
> 现已按 `ΔM/M = [CoC/(CoC−1)]/[CoC_d/(CoC_d−1)] − 1` 重算纠正。
> `CoC` 列原本正确，错误仅限 `M/E` 与 `ΔM/M` 两列。
> 更正后数值与主稿 §5.6、`12_rstar实验_结果与判读.md`、`14_主稿v2增量章节_rstar机制.md` 三处一致。


**关键**：这个增幅与容量**无关**（因为 E 是公因子），只取决于水质参数。这一点由模型实测确认（见 §4）。

## 3 与文献的对接

### 3.1 Saleh 2026（ES&T Viewpoint）

> "Why Water Demand Is No Longer Enough: the challenge extends beyond water quantity to **water compatibility**."

Saleh 提出了问题但没给公式。**r\* 就是这个问题的第一个可计算判据**：它把"水质兼容性"从定性关切变成一个有闭式解、可代入任何城市水质参数的门槛值。

### 3.2 Schwabe 2020（Nat Sustain）/ Tran 2017（Water Res）

Schwabe：室内节水 → 污水收集量下降 → 再生水源减少（**供给侧自噬**）。
Tran：干旱+节水 → 进水浓度上升 → 出水水质下降（**水质侧恶化**）。

**本文的机制是第三条**：
> 即使再生水量充足、水质也合格到"能用于冷却"，**提高替代比例本身**仍会通过混合水质压低浓缩倍数，反而增加补水需求（**配比侧反噬**）。

三者的区别：
- Schwabe 讲的是**池子变小**；
- Tran 讲的是**水质变差**；
- 本文讲的是**混合比例改变**——即使两端水质都合格。

这是一个可区分的、独立的机制。

### 3.3 Badruzzaman 2022（WRI）

实测：沙特油气设施用市政再生水替代地下水，**"提高浓缩倍数可提升水效"**——这正是本文机制的实验依据。他们观察到 CoC 与补水的关系；本文给出**为什么再生水会压低 CoC，以及压到什么比例开始压**。

## 5 为什么这能救论文

### 5.1 它把"描述"升级成"判据"

| 现状（主稿 v1） | 加入 r\* 后 |
|---|---|
| "CoC 下降导致补水上升" —— 作为 263/1027 情景的统计观察 | **闭式判据**：r\* 可由水质参数直接算出，不需要跑模型 |
| "再生水是否有效" 是一个条件题，条件要靠模型算 | 条件变成**可代入的不等式**：`r > r*` 则反噬 |
| 水质是"模型内部参数"（Saleh 批评的正是这个） | 水质成为**承载判据的驱动变量** |

### 5.2 它给出了"什么条件下水质先卡"的答案

主稿现在的瓶颈迁移是"水源/电网"两型。r\* 提供**第三型**的候选：

> 如果城市把 r 推得很高（如 0.8+），补水需求的上升会先吃掉给水厂余量（`max_wtw_utilization`），使**给水能力**先于水源取水失效。

这个假说由新实验直接检验（`run_rstar_bottleneck_experiment.py`）。

### 5.3 它不与 Wang 2026 冲突，而是补它的缺口

- Wang 2026：**用现有 WWTP 尾水**做冷却，证明全球尺度可节水 13 亿 m³；
- 本文：**指出这个结论有配比上限**——当替代率超过 r\*，边际节水开始被反噬侵蚀。

Wang 做的是"能省多少"，本文给出"省到什么时候开始不省"。**这是互补而非竞争。**

### 6.2 明确不声称

- 不声称任何真实城市的 r\* 值（需实测水质参数）；
- 不声称 r\* 是普适常数（它依赖 L、CoC_design、C_r、C_p 四个参数）；
- 不声称反噬一定导致容量下降（它只推高补水需求，是否改变首失效取决于余量结构）。

### 6.3 与"volume-only 路径不一致"的关系

主稿 §7.7(a) 披露的 "volume-only 把循环水限值施加于补水浓度" 的不一致——**本质上是 r\* 机制的粗糙实现**：该路径直接用 `L/C_mix` 当 CoC，忽略设计上限与循环侧动态。

加入 r\* 后，这个"缺陷"可以被重新表述为一个**有意的一阶近似**：
> volume-only 路径等价于假设 `CoC = L/C_mix`（即 r* 机制始终生效、无设计上限）。它与动态路径的差异可按 §2.6 的公式定量预测，不是随机的实现错误。

这样既诚实，又把它纳入理论框架。
