## 1. 从上一轮的结果里找出一句"未经检验的断言"

上一轮发现：Santa Clara 存在 WUE 比湿冷低 315 倍的设施（Bowers，air-cooled + adiabatic）。

论文因此写道：

> "统一按湿冷建模使水耗偏高，故水侧压力结论偏保守。"

**但这句话此前从未被检验。** 而且它有一个危险的含义歧义：

- 若换成 `hybrid`/`dry_first` 后**结论消失** → 那"偏保守"就是错的，实际是"不成立"；
- 若**结论保留但效应量变小** → 那"偏保守"成立，且可以量化出具体幅度。

这两者的差别是"论文能不能投"的差别。必须实测。

---

## 2. 中间踩的一个坑：tech 文件是完整 project 而非 patch

第一次实现时，我把 `tech_*.json` 当作 patch 用 `components.update()` 合并进基线。

实际上它们是**完整的 project 文件**（含全部 12 个组件），这样合并会用 tech 文件的 WTW/WWTW 参数覆盖基线，污染非冷却参数。

修正：**只取 `AI_DC1.cooling` 部分**替换，其余全部保持基线。

> 这一点值得记：一个"看起来像配置片段"的文件实际是完整对象，会导致**静默的参数污染**——不报错、能跑通，但比较的不是同一基线。

## 3. 结果：机制稳健，效应量随技术下降

D-HA 端点，切换 4 个冷却技术档（其余参数保持基线）：

| 技术档 | WUE (L/kWh) | `CoC_d` | 固定 1200 MW 的 r 0.5→0.8 增幅 | 纯物理 CAWCC r=0→0.8 |
|---|---:|---:|---:|---|
| `evaporative` | 2.125 | 5.0 | **+6.478%** | 1200 → 1100（**−100 MW**） |
| `hybrid` | 0.558 | 5.0 | **+6.472%** | 1150 → 1100（**−50 MW**） |
| `dry_first` | 0.327 | **6.0** | **+7.851%** | 1100 → 1050（**−50 MW**） |
| `dry` | 0.000 | 5.0 | **不适用**（取水恒 0） | 1300 → 1300（**0**） |

### 3.1 四点解读

1. **阈值型响应不依赖冷却技术。** 三个有冷却用水的档位**全部保留**该响应（+6.47%～+7.85%）。所以 §5.7 的机制结论**不是湿冷假设的产物**。
2. **效应量随冷却水强度单调下降**：−100 → −50 → −50 → 0 MW。这给"偏保守"提供了**定量内容**：若全市一半设施为 `hybrid`，实际降幅约 **−50 MW** 而非 −100 MW。
3. **`dry` 档必须单独说明。** 其外部取水恒为 0，机制是**"不适用"而非"稳健"**。若不点明，"dry 档降幅 0"会被误读为机制在该档失效。
4. **`dry_first` 增幅反而更大（+7.851%）**，因为它的 `CoC_d = 6.0`，故 `r* = 0.3972`（低于 0.5532），更早跨阈值。这是 `r*` 对 `CoC_d` 高弹性（−1.69）的又一个具体实例。

### 3.2 对论文的影响

**正面**：核心机制结论对外部技术构成**稳健**——这是审稿人会问的问题（"你的结论是不是湿冷假设的产物？"），现在有答案了。

**需要如实下调**：−100 MW 应理解为**湿冷上限情形**。若真实城市的技术构成更偏风冷，效应量会更小（约 −50 MW）。已写入 §5.8.7 与 SI S7.14。

## 4. 又一次被门禁抓到的手算错误

写核验脚本时我断言 `r*(CoC=6) = 0.3549`，门禁报错，实际是 **0.3972**。

手算核对：`(2200/6 − 180)/(650 − 180) = (366.67 − 180)/470 = 0.3972`。

0.3549 是我凭印象写的。**门禁在这里的价值不是"防我改坏代码"，而是"防我用记忆代替计算"。**

## 6. 方法论收获

### 6.1 "保守"是一个可被检验的定量陈述，不是免责声明

论文里写"我们的假设偏保守"时，读者会问：保守多少？如果结论在保守假设下就消失，那"保守"反而成了软肋。

**把"偏保守"变成"−100 是上限，实际可能是 −50"，比只说"偏保守"强得多**——前者是定量边界，后者是修辞。

### 6.2 静默的参数污染是最难发现的一类错误

`tech_*.json` 是完整 project 而非 patch。若按 patch 合并，会覆盖 WTW/WWTW 参数，**不报错、能跑通、结果看起来合理**，但比较的不是同一基线。

**防这类错误的方法是对比"应当不变的量"**：本次的正确做法是只替换 `AI_DC1.cooling`，这保证了其余组件逐位不变。若当时加一条"非冷却参数哈希不变"的断言，就能立刻抓到。

### 6.3 记忆不能代替计算

`r*(CoC=6)` 我"记得"是 0.3549，实际 0.3972。这类错误在正文里完全看不出来（数字都很像），只有独立复算能抓到。
