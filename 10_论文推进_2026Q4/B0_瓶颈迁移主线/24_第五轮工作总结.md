**目标**：继续推进到 Nature 子刊级。
**本轮性质**：**不增加新科学内容，而是修复"局部更新、全局未同步"的系统性缺陷，并建立机器检查。**

## 一、本轮发现的核心问题

这类缺陷的特征：
- **不报错**；
- **每处单独看都通顺**；

**即：前三轮的核心贡献有一半没进摘要。**

### 2.2 新摘要的结构（1,984 字，五段式）

| 段 | 内容 |
|---|---|
| 开篇 | 问题：替代率被当作自由参数，代价未被量化 |

| **第三** | **四情形分类学**（I/II/III/IV，三情形实证 +20.74% / +6.48% / 0.00e+00%，情形 I 的 CoC=12.22≠15） |
| **第四** | 纯物理口径 −100 MW + 混淆排除（电网 Δ=0.0000） |
| **第五** | **零效应区是可证伪预测而非缺陷** + 口径区隔（`r_max = u·(W/D)`） |
| 结尾 | 不声称真实城市容量；两口径不得混报 |

### 2.3 摘要数字的独立溯源

新建 `_verify_abstract_numbers.py`，逐条核对摘要中的**每一个小数**：

- 摘要共出现 24 个不同小数；
- **全部 26 项核对通过**；
- **"摘要全部小数均出现在正文"——缺失 0**。

这一步很关键：摘要数字若无法溯源，是审稿人最容易抓的硬伤。

## 三、建立"同步性检查"（本轮的机制性产出）

### 3.1 为什么需要

这是**第二次**发现同类缺陷（前一次是 §5.6 与 §9.2 关于阈值扰动的矛盾）。人工警觉不可靠，必须机器检查。

### 3.2 检查规则（`_check_sync.py`，9 项）

| 规则 | 内容 |
|---|---|
| **R1** | 首行标明 v2；状态行为定稿候选；无 v1 草稿残留 |
| **R2** | 摘要必须覆盖 11 个核心关键词（r\*、四情形、情形命名、W/D、判据定位、0.6842、精确为零、可证伪、纯物理、双因素、三情形实证） |
| **R3** | 各章"结论"段必须提及本章新增的核心概念（如 §7 结论必须含"配比"与"三"） |
| **R4** | §1.3 声称的贡献数 = 实际条目数 |
| **R5** | §9 限制编号连续 |
| **R6** | 交叉引用的节号必须存在（含 §7.7a–d 这类括号编号） |
| **R7** | 无"本轮新增""v2 新增"等过程性标记残留 |

**R2 与 R3 是新增的规则类型**：前者检查"概述是否覆盖细节"，后者检查"结论是否覆盖本章"。这两类正是前四轮反复出问题的地方。

### 3.3 结果

初次运行 8/9（R7 发现 4 处过程标记）。清理后 **9/9**。

## 四、清理过程性标记

发现 4 处不该出现在定稿中的工作痕迹：

- `（**本轮新增，论证重心之一**）` → 删除
- `（v2 新增）` × 2 → 删除
- `### 7.0 本章重组：从两杠杆到三杠杆（v2 新增）` → 改为 `### 7.0 本章的结构：从两杠杆到三杠杆`

**连带影响**：两处门禁脚本的断言文本因此过时（`_audit_v2.py` 与 `_final_check.py` 都在找"### 7.0 本章重组"）。已同步更新断言，而非回退正文——**正文正确性优先于脚本便利性**。

## 五、§7.6 结论的修补

**旧结论**只讲两个杠杆：

> 再生水不是"不能提升承载容量"，而是"只有在它真正增加产水量、且瓶颈位于水源侧时才能提升"。仅扩大处理能力在两端点都完全无效；提高产水量在缺水端可使承载容量提升约 300 MW 并把瓶颈迁移到电网……

**问题**：§7.0 已把本章重组为三杠杆，结论却只谈两个。

**新结论**改为三杠杆并列表：

| 杠杆 | 机制 | 效果 |
|---|---|---|
| **处理能力** | 供给侧"名不副实" | 两端点均完全无效 |
| **产水量** | **供给增量** | 缺水端 +300 MW 并迁移瓶颈至电网 |
| **配比 r** | **需求膨胀** | ≤r\* 零代价；>r\* 后 −100 MW |

并补一句关键的辨析：

> **三者不可混谈。** "扩处理能力"与"提产水量"是供给侧的量变，"提配比"则是通过水质侧改变了需求——方向相反。若把三者笼统地称为"扩大再生水利用"，会得到自相矛盾的规划结论。

## 七、本轮的诚实清单

1. **本轮没有新增科学内容。** 所有发现都是"已有的东西没同步"。这在投稿前是必要的，但不能算科学进展。
2. **摘要重写没有改变任何数值**，只是把已核实的结论重新组织进摘要。
3. **同步性检查只能查"关键词是否出现"**，不能判断论证是否真的连贯。它防的是低级遗漏，不能替代人工通读。
4. **§7.6 的修补引入了新的表述**（三杠杆表），但所有数字都来自已核实的产物。
5. **过程性标记清理后，两处脚本断言失效**——说明检查脚本本身也需要维护。这是一个已知的脆弱点。
