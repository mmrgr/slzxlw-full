# 第二十六轮工作总结：撤回「两条路径上下界」结论，并重建正确的路径依赖表述

**日期**：2026-10-19
**轮次**：26
**触发**：上一轮（25）把「动态盐分路径下 −100 MW 效应消失」解释为「24 ML 储池缓冲」，
并据此在母稿 §5.7.9「事实三」、§5.7.10、英文稿 §3.2、SI S5.10/S5.11 四处写成
「两路径构成上下界（legacy=上界 100 MW，dynamic=下界≈0）」。
本轮复核发现**该解释错误**，已全面撤回并重建。

## 1. 发现：动态路径的补水几乎不含盐

复核起点是一个物理反常：§5.7.9 记录「排污 TDS 由 1998 降至约 194 mg/L」，
并把它当作「盐被存进储池」的证据。但 r=0.9 时按声明值的混合补水应为
`0.9×650 + 0.1×180 = 603 mg/L`，**排污浓度低于补水浓度在稳态下不可能**。

顺着这条线索追查（`_diag_dynamic_inflow.py` → `_diag_reuse_quality.py` → `_diag_reuse_tds_rootcause.py`），
根因是一条完整的链条：

1. 两个端点项目的市政污水负荷只声明了 `{BOD: 0.06, TSS: 0.07} kg/人/日`，**没有 TDS / chloride**
   （`examples/cawcc_r2/{ha,co}/project.json` → `local_areas.LA1.sanitary_pollutant_load_kg_capita_day`）。
2. `WWTW1` 声明了 `pollutant_removal_fraction.TDS = 0.05`，但**没有 TDS 入流可去**。
3. `CENTRAL_REUSE` 组件**没有任何 `quality` 声明**。
4. 因此 WWTW 的 `pollutant_storage["TDS"]` 几乎只累积数据中心自身排污的那一点盐。
5. `full_engine._reuse_output_quality()`（`full_engine.py:195-229`）用
   `pollutant_storage` 的 `mass/volume` **覆盖**了
   `AI_DC1.water_sources.reclaimed.quality.TDS = 650`。
6. 结果：动态路径的 $C_r$ 实测中位 **8.27 mg/L**，是声明值的 **1.3%**（差 77 倍）。

**因此「CoC 锁在 5.0、补水不随 r 变」的成因是「补水无盐」，不是「储池缓冲」。**

## 2. 2×2 归因设计（决定性证据）

`_diag_2x2_attribution.py`，D-HA，1100 MW，730 日：

| 路径 | 市政 TDS 入流 | $C_r$ 中位 mg/L | r=0.5 补水 ML | r=0.9 补水 ML | 变化 |
|---|---|---:|---:|---:|---:|
| legacy | 缺 | 650（声明值，不走质量账本） | 30,770.8 | 33,655.1 | **+9.373%** |
| legacy | 补齐 | 650（同上） | 30,770.8 | 33,655.1 | +9.373% |
| 动态 | 缺 | **8.27** | 30,770.8 | 30,774.3 | **+0.011%** |
| 动态 | 补齐 | **650.30** | 30,876.4 | 33,149.8 | **+7.363%** |

- 锁定效应**只出现在「缺 TDS」格**，补齐后即消失（0.011% → 7.363%）。
- legacy 两格逐位相同 → 证明 legacy 路径确实不读质量账本（自洽性检查通过）。

**末态判据**（比「排污变淡」更有力）：

| 量 | 实测 | 若为储池缓冲应有 |
|---|---:|---:|
| 环内 process TDS 末值 | 36.54 mg/L | ≈603 mg/L |
| 排污 TDS 末值 | 182.69 mg/L | 3015 mg/L（=603×5） |
| 两者之比 | **5.000**（=设计 CoC） | 5.0 |

排污实测仅为应有值的 **6.06%**。比值恰为 5.000 说明**模型没有绕过浓缩**，
环路照常按 CoC 5.0 浓缩——低的是进口浓度本身，不是"盐被存起来了"。
若真是储池缓冲，环内浓度应仍接近 603 而只是排污滞后；实测与之相反。

## 5. 更正后的表述

1. **`r*` 的解析式与四情形分类学完全不受影响**——代数结论，与路径无关。
2. **反噬方向在两条路径下都成立**：提高 r 都使取水上升、CAWCC 下降。
3. **量级依赖路径**：legacy 100 MW / +9.373%，动态 50 MW / +7.363%。
4. **−100 MW 与 +6.48% 是 legacy 路径的值，应读作「该建模约定下的上端估计」**，
   而非稳健点估计。
5. **保留 legacy 作主情景的理由**（已重写）：它与解析推导用同一 CoC 表达式（对到 1e-15），
   且不需要反标定缺失的污水盐负荷；代价是给出上端量级，已在正文与 SI 明示。

## 8. 本轮方法论教训（已记入长期清单）

1. **物理不自洽是发现 bug 的最强信号。** 排污浓度低于补水浓度在稳态下不可能——
   这个反常本应在上一轮就拦住「储池缓冲」的解释，但当时被「储池暂存盐分」的叙事
   合理化掉了。
2. **"解释得通" ≠ "验证过"。** 上一轮的储池缓冲解释在定性上自洽、在数值上也能对上
   （24 ML 储池、满库、排污变淡），但从未检验输入本身是否正确。
3. **归因需要正交设计。** 只切换 `quality_state_enabled` 一个因子，无法把
   「路径机制」与「输入不一致」分开；必须做 2×2。
4. **末态比值是强判据。** `182.69/36.54 = 5.000` 精确等于设计 CoC，一举证明
   环路没有绕过浓缩——比"排污变淡了"有判别力得多。
5. **撤稿式更正要写进正文。** 不是悄悄改掉，而是明确写"上一版本判断错误，现予撤回"，
   并给出决定性证据。这既是对读者的尊重，也是可复现性的要求。
