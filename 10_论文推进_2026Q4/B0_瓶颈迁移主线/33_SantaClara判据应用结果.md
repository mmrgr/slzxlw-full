# Santa Clara 真实城市判据应用：结果与解读

**日期**：2026-10-18
**数据**：`2025 Urban Water Management Plan_Final.pdf`（282 页，市府法定文件）+ 市府 staff presentation p.27
**性质**：**本文 `r*` 判据第一次应用于真实城市**

---

## 一、核心结果

| 口径 | P (AF) | R (AF) | k = P/R | **r** | 判定 |
|---|---:|---:|---:|---:|---|
| **A 供给能力**（正常年，p.65） | 32,649 | 6,017 | 5.426 | **0.4440** | 未越过 |
| **B 2025 实际用量**（p.35） | 16,857 | 3,871 | 4.355 | **0.4988** | 未越过 |

**判据阈值 `r* = 0.5532`。两口径均未越过，但实际用量口径已相当接近。**

**距离：r = 0.4988，距 r\* 仅差 5.44 个百分点（相对余量 9.8%）。**

## 三、计算过程

### 3.1 换算公式

6% 与 26% 是"数据中心占**全市总量**的份额"，而本文的 `r` 是"园区**内部**的再生水配比"。两者关系：

```
设全市自来水用量 P、再生水用量 R
数据中心用自来水 = 0.06P，用再生水 = 0.26R
园区总补水 D = 0.06P + 0.26R

r = 0.26R / (0.06P + 0.26R) = 1 / (1 + (6/26)·k)，其中 k = P/R
```

### 3.2 临界值

令 `r = r* = 0.5532`，解出：

```
k* = (1/0.5532 − 1)/(6/26) = 3.500
```

**即：全市自来水与再生水之比低于 3.50 时，数据中心园区进入水质反噬区。**

### 3.3 代入实际数据

**口径 B（2025 实际用量）**：

```
k = 16,857 / 3,871 = 4.355

数据中心用再生水 = 26% × 3,871 = 1,006.5 AF
数据中心用自来水 =  6% × 16,857 = 1,011.4 AF
园区总补水 = 2,017.9 AF

r = 1,006.5 / 2,017.9 = 0.4988
```

`r = 0.4988 < r* = 0.5532` → **未越过阈值**。

## 四、这说明了什么

### 4.1 正面结论

1. **判据可以应用于真实城市。** 只需三个二手数据（6%、26%，以及全市 P/R），就能算出真实城市的园区配比 r。
2. **Santa Clara 尚未越过阈值，但余量不大**（9.8%）。
3. **两口径一致性**：供给能力口径 r=0.4440、实际用量口径 r=0.4988，都低于 r\*，判定稳健。

### 4.2 一个重要的结构性观察

**实际用量口径的 r（0.4988）比供给能力口径的 r（0.4440）更接近阈值。**

原因：
- 城市总用量（20,728）远低于供给能力（38,666）——**城市在低负荷运行**；
- 但再生水系统实际利用率 = 3,871 / 6,017 = **64.3%**，**再生水系统比全市供水系统更紧张**。

→ **这恰好印证了本文的机制直觉**：当城市整体有余量时，制约数据中心配比的不是"总水量"，而是**再生水子系统的相对紧张度**。

### 4.3 关于"何时会越过"的定量推演

| 变化 | 阈值条件 |
|---|---|
| 再生水用量 | 需从 3,871 增至 **4,816 AF**（+24%） |
| 或：自来水用量 | 需从 16,857 降至 **13,548 AF**（−20%） |
| 或：k | 需从 4.355 降至 **3.500**（−19.6%） |

**现实含义**：数据中心继续扩张（再生水用量上升），而城市自来水用量不变 → k 自然下降 → **逼近并可能越过 k\***。

**这是本文判据给出的可检验预测**：若 Santa Clara 的数据中心再生水用量在现有基础上再增 24%，就将进入反噬区。

## 五、必须携带的限定（写入论文）

1. **6% 与 26% 是"全市份额"，不是园区配比。** 市府文件的第三方证据台账（Item 7 后段 p.53）明确警告：
   > "Separate water-system denominators; **not 32% of combined use**. Supporting period and volumes need disclosure."

   → 两者**不可加总为 32%**，且**统计时段未披露**。

2. **6%/26% 只存在于图形中。** 市府 staff presentation p.27 的 PDF 文本层没有这两个百分比，必须渲染读图。这意味着**任何纯文本抓取的做法都拿不到原始数据**。

3. **口径选择影响结果，但两口径同向。** 供给能力口径 r=0.4440、实际用量口径 r=0.4988，都低于 r\*。**本文采用实际用量口径（B）为主，供给能力口径（A）为辅。**

4. **数据是年度总量，不是逐设施。** Santa Clara 有 56 座数据中心（市府报告与 OSM 独立计数一致），但**没有逐设施用水量**。本文的 r=0.4988 是**全市场均值**，不代表任一具体设施。

5. **"未越过"不等于"无代价"。** 由 §4.3，r 距阈值仅 9.8% 余量。且本文的 `r*` 判据本身有参数不确定性（`L`/`CoC_design` 各 ±10% 使 r\* 移动约 0.05–0.09），**若 r\* 实际为 0.51，Santa Clara 则已越过**。

## 六、对论文的价值

### 6.1 这是本文最强的现实性证据

| 之前 | 现在 |
|---|---|
| 全部数字来自合成端点 | **有一个真实城市的官方数据 + 判据应用** |
| `r* = 0.5532` 无现实参照 | **算出 Santa Clara 的 r = 0.4988，距阈值 5.4 个百分点** |
| 只能声称"机制成立" | **可以声称"机制在一个真实重度回用城市中接近触发"** |

### 6.2 一个意外收获：`k* = 3.500` 本身是可推广的

论文可以给出一个**比 `r*` 更易操作的判据**：

```
若某城市的 全市自来水/再生水 之比 k < 3.50，
则其数据中心的园区再生水配比必然超过 r* = 0.5532，进入水质反噬区。
```

**这个判据只需要两个数（全市自来水总量、再生水总量）**，比逐设施计算容易得多。

### 6.3 但必须诚实：这不是"验证"，是"应用"

- **应用**：把判据代入真实参数，得到一个可检验的预测（r=0.4988，距阈值 9.8%）。
- **验证**：需要观测到"当 r 越过 0.5532 时，补水需求确实上升"。**这需要逐设施时序数据，本文没有。**

→ 论文只能称前者（应用），不能称后者（验证）。
