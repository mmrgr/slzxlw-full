# 主稿 v1 → v2 修正清单（含一处真实口径错误）

**日期**：2026-10-18
**触发**：`_verify_v2_numbers.py` 核对时发现 `reuse_marginal_curve.csv` 的 CAWCC 为 1100，而主稿 §7.5 写的是 1150。

---

## 修正 1（重要）：§7.5 处理能力杠杆混用了两个网格口径

### 1.1 问题

主稿 v1 §7.5 的表格写作：

| 杠杆 | D-HA 结果 | D-CO 结果 |
|---|---|---|
| **仅扩处理能力** | CAWCC **恒 1150 MW**，边际增益恒 0 | CAWCC **恒 1450 MW**，边际增益恒 0 |
| **提高产水量** | CAWCC **1100 → 1400 MW**（+300） | CAWCC 恒 1400 MW |

**这里混用了两个网格：**
- "1150 / 1450" 是 **50 MW 网格**的主结果（`capacity_threshold_corrected.json` 的 `physical_daily`）；
- "1100 / 1400" 是 **100 MW 网格**的曲线产物（`reuse_marginal_curve.csv`、`reuse_production_marginal_curve.csv`）。

### 1.2 实测证据

```
reuse_marginal_curve.csv (HA):  cawcc_mw 全为 1100.0（7 个处理能力档位）
reuse_marginal_curve.csv (CO):  cawcc_mw 全为 1400.0（7 个档位）
capacity_threshold_corrected.json (HA).physical_daily.maximum_safe_ai_capacity_mw = 1150
capacity_threshold_corrected.json (CO).physical_daily.maximum_safe_ai_capacity_mw = 1450
```

两个口径差值恒为 50 MW（= 网格步长的一半）。

### 1.3 为什么这是错误而非笔误

**同一张表里，第一行用 50 MW 网格的 1150，第二行用 100 MW 网格的 1100。** 读者会自然地认为：
- "仅扩处理能力，CAWCC 恒 1150"；
- "提高产水量，CAWCC 从 1100 升到 1400"；

于是隐含推出"提高产水量先损失 50 MW，再涨 300 MW"，或"两者基点不同但可比较"。**这两种理解都不成立。**

主稿 §3.6 已经非常清楚地警告过同类错误（"跨网格相减会产生伪值"），但 §7.5 自己没有遵守。

### 1.4 修正方案（v2 采用）

**方案：全部改用该曲线的同网格口径，并显式声明。**

| 杠杆 | D-HA（100 MW 网格口径） | D-CO（100 MW 网格口径） |
|---|---|---|
| 仅扩处理能力 | CAWCC **恒 1100**，边际增益恒 0 | CAWCC **恒 1400**，边际增益恒 0 |
| 提高产水量 | CAWCC **1100 → 1400**（+300），瓶颈迁移至电网 | CAWCC **恒 1400**（不动） |

**并在表下加注**：

> ⚠️ **口径声明**：本表两个杠杆均取自 100 MW 网格的边际曲线产物（`reuse_marginal_curve.csv` / `reuse_production_marginal_curve.csv`），基点为 HA 1100 / CO 1400 MW。**与主结果（50 MW 网格，1150 / 1450）不可做算术**。若要得到 50 MW 网格上的对应值，需按同网格重跑这两个杠杆——**本文未做**，列为待办。

### 1.5 这项修正是否影响任何结论

**不影响定性结论，只修正数值归属**：

| 结论 | 是否改变 |
|---|---|
| 仅扩处理能力零增益 | ❌ 不变（边际增益恒为 0，与网格无关） |
| 提高产水量可使瓶颈从水源迁移到电网 | ❌ 不变（限制约束 `max_source_abstraction_ratio → max_daily_average_grid_connection_ratio` 的迁移在该曲线内清晰可见） |
| "有效杠杆"与"无效杠杆"的分野 | ❌ 不变 |
| 具体 MW 数值 | ✅ 改为 1100/1400，并声明为 100 MW 网格 |

## 修正 2：新增 §5.7/§5.8 后，§5.6 的"未做阈值扰动"表述已过时

主稿 v1 §5.6 写「**迁移点未做 ±2% 阈值扰动敏感性检验**。这是本文的已知缺口（见 §9.2）」。

但 §9.2 第 5 条已经记载该检验**已完成**（`threshold_perturbation_summary.json`，HA 极差 250 MW、CO 极差 50 MW）。**§5.6 与 §9.2 自相矛盾。**

### 修正

§5.6 该条改为：

> **迁移点的阈值扰动敏感性已检验**（见 §9.2 第 5 条）：HA 日尺度 CAWCC 极差 250 MW（约 75 MW / 1% 阈值），CO 极差 50 MW；但迁移结构稳健——HA 首失效落在 1000–1350 MW（水源侧），CO 落在 1450–1500 MW（电网侧），两域区间不重叠。

## 修正 3：§7.2 的"263/1027"与新增 r\* 机制的关系需要重述

主稿 v1 §7.2 写道：

> 在多数情景下，AI 改用再生水后其外部补水需求反而略升。原因是再生水掺混降低冷却浓缩倍数（CoC），使单位散热所需补水量上升……

**这段已经把 r\* 机制的经验形态说出来了**，但它：
1. 定位为"1027 个情景中的一个统计子集"（263/1027）；
2. 未给出判据，未给阈值；
3. 未与承载容量联系起来。

### 修正（v2）

保留该统计，但**在其后追加一段指向 §5.7**：

> 这一现象在本文 §5.7 得到解析解释：它不是情景间的偶然散布，而是 `CoC = min(CoC_design, L/C_mix)` 这一结构的必然结果。临界替代率 `r* = 0.5532` 可由水质参数闭式算出；超过它后补水需求单调上升，且该效应与容量无关。**上述 263/1027 是这一机制在参数抽样下的经验投影。**

这样，原有的经验统计不再是孤立观察，而是新判据的**大样本佐证**。

## 修正 4：核对脚本本身的判定条件过严（非主稿问题）

`_verify_v2_numbers.py` 中"取水增幅与容量无关"一项用了 `round(v, 2)` 相等判断，而实测值为 6.4661 / 6.4765 / 6.4777 / 6.4782，四舍五入后为 6.47 / 6.48 / 6.48 / 6.48，不满足"全部相同"。

**判定条件应改为"极差 < 0.02 个百分点"**。实测极差 = 6.4782 − 6.4661 = **0.0121 个百分点**，远小于判据。

**这不是主稿的问题**：文章表述"一致为 +6.47%～+6.48%"是准确的。

## 一个自我检查：为什么这个错误能存活到 v1

v1 的核心关切是"不要跨网格相减产生伪值"，因此 §3.6 对干预增益写得极其谨慎（甚至列出 −50 MW 伪值的完整来龙去脉）。

但 §7.5 的**两个杠杆曲线**看起来像"独立的扫描结果"，不像"与主结果同一数量的两种测法"，于是口径混用没有被识别。

**教训**：口径纪律不能只施加于"明显要相减的地方"，还要施加于**同一张表里并列出现的任何两个数值**。v2 的核对脚本把这条变成了机器检查（每个数值都必须带口径标签），而不是靠人工警觉。
