## 1. 问题①：`chi` 的**两套冲突定义**（核心）

### 1.1 现状

| 位置 | `chi` 的含义 | 取值 | 是否有 `limit_scale` 列 |
|---|---|---|---|
| **`T12_surface.csv`（正确）** | `chi := CoC_lim / CoC_design`（无量纲严格度） | 0.078 … 1.0（连续） | ✅ 有（两者并存） |
| `A13c potable_flows` | **就是** `limit_scale` | 0.25 / 0.5 / 1.0 | ✅ 已加（A25） |
| `A15 ablation / holdout` | **就是** `limit_scale` | 0.25 / 0.5 / 1.0 | ❌ 无 |
| `A17 supply_state_regimes` | **就是** `limit_scale` | 0.25/0.5/0.98/**1e6** | ❌ 无 |
| `A22 derived/q_predictors` | 继承 A17 | 同上 | ❌ 无 |
| `fig1_v2_source_*` | 继承 A13c/A15 | 0.25/0.5/1.0 与 0.5/1e6 | ❌ 无 |

### 1.2 风险

**同名不同义，且数值区间重叠**：
- 在 T12 中 `chi = 0.25` 表示"严格度 0.25"（CoC 被压到设计的 25%）
- 在 A13c 中 `chi = 0.25` 表示 `limit_scale = 0.25`（限值整体缩放 25%）
- **两者数值相同但含义不同**，跨表合并或对比会静默出错。
- 更危险：`chi = 1.0` 在 T12 是"刚好到设计值"，在 A13c 是"仍受约束"，
  而 A17 用 `1e6` 表示"真不约束"——**三处对"1.0"的理解都不同**。

### 1.3 修法（不改数值，只消除歧义）

**原则**：保留各脚本既有数值口径（改动会波及全部下游数字），
但**在每个产物中显式输出两列并加禁用声明**：

1. 统一新增列：
   - `limit_scale` —— 传给引擎的真实缩放因子（**权威列**）
   - `chi_strictness` —— `CoC_lim_realized / CoC_design`（无量纲严格度，由引擎实测反解）
   - `quality_binding` —— 布尔：`chi_strictness < 1 - tol`（是否真的受约束）
2. **废弃裸 `chi` 列**：保留但重命名为 `chi_LEGACY_EQUALS_LIMIT_SCALE`（A13c/A15/A17/A22）
   或 `chi_strictness`（T12 保持不变，因其定义本就正确）。
3. 在 `A26_语义统一/CHI_SEMANTICS.md` 写一张**权威语义表**，所有文档引用它。

**为何不直接统一改名为 `limit_scale`**：A17/A22 的 `chi_label`（`free`/`0.98`/`0.50`/`0.25`）
已被主稿与 SI 引用，改名会破坏可追溯性。故采用"保留+加注+新增权威列"策略。

## 3. 问题③：T2 的 50% 未收敛 —— **误报，非问题**

### 3.1 侦察结论
`T2_cell_results.csv` 的 320 行 `quality_not_converged` **全部是 `Q0` 单元格**：

| Q | `coc_mode` | 调用水质求解器? | status 字段 |
|---|---|---|---|
| **Q0** | `fixed` | **否** | 占位值 `quality_not_converged` |
| **Q1** | `quality_limited` | 是 | `converged_unique` |

**证据**：
- 交叉表完全对角（Q0↔quality_not_converged 320/320；Q1↔converged_unique 320/320）
- Q0 与 Q1 的 `closure_residual` 与 `fp_residual` **均为 0.000e+00**
- 全部 640 行的 `S_city_ml` 均有值
- 且 `P0`/`gap` 来自独立的 φ=0 基线运行，**与这 640 个单元无关**（A25 已证）

### 3.2 处置
**不改数值**，只做两件事：
1. 在 T2 产物中把该列改名为 `quality_solver_status` 并加注
   "Q0 单元格不调用水质求解器，此列为占位值"；
2. 在 `CHI_SEMANTICS.md` 的"状态词表"节登记此例外，
   避免后续审计再次误报（**这就是我上一轮误报的根因**）。

### 6.1 ★ 意外收获：名义档 ≠ 实际约束档

新增 `quality_binding` 列后暴露出一个**此前被单一 `chi` 列掩盖**的事实：

| 名义 `limit_scale` | **实际生效（受约束）比例** |
|---:|---:|
| 0.25 | 100% |
| 0.50 | 92% |
| 0.98 | **58%** |
| 1.0 | **48%** |
| 1e6 | 0% |

> **在 `limit_scale=0.98` 档，有 42% 的情景实际已达到设计上限、并未受水质约束。**
> 因此"按名义档位分组做统计"会把**两种不同物理机制**混在一起。
> 已把该发现写入 SI §S2b，并在所有分档统计中并列报告 `quality_binding`。
