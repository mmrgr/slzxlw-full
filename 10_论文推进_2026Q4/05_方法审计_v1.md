## A 级：推翻或必须重定义（5 条）

### A1. T9「无量纲折叠」是代数恒等式，不是发现；Gate G-B 不构成 gate ★最严重

T9 的折叠式

```
y = Φ·(w − u),   w = φ_eff·δ,   δ ≡ 1 − (pool − inc_recl)/x_ai,   u = 1 − 1/Φ
```

把 δ 的定义代入即可发现它是恒等式：

```
φ_eff·δ = (x_ai/M)·[1 − (pool − inc_recl)/x_ai] = (x_ai + inc_recl − pool)/M
Φ·(w−u) = (M/m0)·[(x_ai+inc_recl−pool)/M − 1 + m0/M]
        = [m0 − M + x_ai + inc_recl − pool]/m0
        = S_city/m0                              （正是代码里的 y_num）
```

而代码第 328 行 `delta = 1.0 − (pool − inc_recl)/x_ai` 正是**为了让等式成立而被这样定义**的。
所以：

- 残差 1.78e-15、R² = 1.00000000 **在数学上必然如此**，与物理、与引擎、与抽样都无关；
  （**数值更新**：修复轮重跑后冻结值 `max|Δy| = 7.11e-15`、降维比 19.4×；同为机器精度，结论不变。）
- "6 个维度 → 2 个无量纲群"是把 6 个量**【重参数化】成 2 个量**，不是降维。δ 本身是
  (pool, gap, ΔP, 分配结果) 的函数，它把待解释的变异搬进了坐标轴里；
- 因此 Gate G-B（`残差<1e-6 且 散度比>3`）**不能作为"可迁移性成立"的证据**。

阶段报告 §6.1 已经承认"证明的是引擎没引入第三个变量"，但**标题与 Gate PASS 的结论没有相应降级**。

> 影响：论文里"可迁移性"这一栏目前是**空的**。真正要证的是：δ 能否由**外生**城市参数
> (P₀, gap, ΔP, 目标掺混比, 用水权规则) 预测出来——这恰恰是 T9 没做的。

### A3. T1「规则不变性」同样由定义强制，且 F1 检验对 4 条规则中的 2 条是平凡通过

`fixed_point()` 里：

```
s_city = s_ai − displacement,   displacement = pool − inc_recl
```

只要分配结果把池分完（`ai + inc_recl = pool`），就恒有 `displacement = ai`，从而
`S_city = m0 − M`。这不是规则造成的，而是**"池被分完"这一条件**造成的。

更具体的：θ=0（固定池、无扩容）时

| 规则 | AI 实得 | 为什么 |
|---|---|---|
| `engine_native` | > 0 | 从存量池取 |
| `pro_rata` | > 0 | 瓜分存量池 |
| `incumbent_first` | **恒为 0** | 池先被既有用户占满，增量预算 = 0 |
| `dedicated` | **恒为 0** | ΔP = 0，专用增量 = 0 |

即"四种规则最大 S_city 全为 0"里，有**两种规则是因为 AI 根本没拿到水**才为 0，
与"规则不变性"无关。F1 判据因此有 1/2 是平凡通过。真正有信息量的是前两种规则
（S_city = m0 − M ≤ 0）——而这一条见 D1。

### A4. T8「全链溶质闭合」指标定义错误，报告把 2.8% 写成了 ~1e-16 ★

`T8_solute_closure.py` 第 111 行：

```python
"closure_rel": abs(inflow - out_drift - out_bd) / max(inflow, 1e-12)
```

稳态质量守恒应为 `inflow + recirc = drift + blowdown`，所以
`inflow − drift − blowdown = −recirc`，**这个量按构造就不为零**——它等于
"内部回收返回循环的质量份额"，不是闭合误差。产物 `T8_summary.json` 里

```
"closure_rel_max": 0.027939392693406968      ← 2.79%
```

而阶段报告 `03_阶段结果_T2-T8.md` §2.1 写的是"闭合相对残差 **~1e-16 量级**"。
两者相差 14 个数量级。**真正的全链溶质闭合（含回流项）从未被检验。**

（唯一 ~1e-12 的是 `partition_blowdown_solutes` 自己的内部分割残差，属模块内部一致性。）

### A5. T6 的 χ 无上限，导致"跨 200×"是度量假象

`χ = CoC_lim/CoC_design` 未做任何截断，于是 LADWP RO 产水给出 `CoC_lim = 70.4`、
`χ = 14.08` —— 但**没有任何冷却塔会在 CoC=70 下运行**，且引擎自己就是
`min(design, min(ratios))`（`data_center.py` `_cycles_of_concentration`），
即引擎层面 χ 的有效上界是 1.00。

- 报告：`χ ∈ [0.07, 14.08]`，"跨 200×"；
- 按引擎口径：`χ_eff = min(CoC_lim, 5)/5 ∈ [0.07, 1.00]`，实际跨度 **14×**。

`χ` 只有在 < 1 时才表达"水质构成约束"，> 1 的部分没有物理含义。建议改为
`χ = min(CoC_lim, CoC_design)/CoC_design`，并重述跨度。

## B 级：方法学缺陷（会被审稿人抓）

### B1. T6 把"保守物种判据"与"沉淀物种判据"混在一个 min 比值里

`coc_lim()` 对所有物种一律用 `limit/concentration` 的线性浓缩比。这对 TDS/Cl/SO₄ 成立
（保守），但 **hardness、alkalinity、silica 恰恰是非保守的**——它们在冷却塔内以
CaCO₃ / Mg(OH)₂ / SiO₂ 形式**沉淀**，其约束来自矿物饱和度（LSI/RSI/SI），不是浓度比。

而结论"限值物种是 alkalinity ×2 / hardness ×1"完全建立在这个比值法上。
预注册 §7 明确承诺"① 工程限值判据；② 矿物饱和度判据；**分别报告，不混合**"，
并点名这是 GPT 指出的 P0 问题——**但代码里只有比值法一种，承诺未兑现**。
（仓库内 `run_g2_phreeqc_crosscheck.py` + 已装的 phreeqpython 本来可以做，没做。）

### B2. "panel A vs panel B"不是干净的限值集操作，与样本完整性混淆

`quality_dict()` 会**丢弃缺失物种**。5 个水样的完整度差异极大：

| 水样 | TDS | Cl | hardness | alkalinity | silica |
|---|---|---|---|---|---|
| IEUA | ✔ | ✔ | ✔ | ✔ | ✔ |
| LADWP | ✔ | ✔ | ✔(仅 Ca) | ✔ | ✔ |
| Figshare RW | ✔(估) | ✘ | ✔ | ✘ | ✘ |
| Figshare BW | ✔(估) | ✘ | ✔ | ✘ | ✘ |
| 模型假定 | ✔ | ✔ | ✘ | ✘ | ✘ |

于是 panel B 对 RW/BW 只是"TDS+hardness"，对"模型假定"干脆等于 panel A。
**panel 之间的差同时包含"限值集变化"与"样本可得性变化"，无法归因。**

### B3. 阈值来源是引擎里的占位值，不是标准

`data/ai_data_center_database.json`：

```
"hardness":   {"value":700, "source":"site-specific design placeholder", "type":"assumption"}
"alkalinity": {"value":500, "source":"site-specific design placeholder", "type":"assumption"}
"silica":     {"value":150, "source":"site-specific design placeholder", "type":"assumption"}
```

T6 把这些当作"阈值与引擎一致（只读）"，但它们是**未引用的占位假设**。
"限值物种是 alkalinity"这一结论对该占位值极敏感（碱度限值 500→300 时
IEUA 的 CoC_lim 从 3.57 降到 2.14）。必须换成有出处的冷却水水质准则并做敏感性。

### B4. T2 的四格 Ld/Ls 不干净：同时改了 claim 和 capacity

```python
if l_mode == "Ld": inc_inc, inc_cap = p0, p0
else:              inc_inc, inc_cap = 0.0, gap
```

L 的变换同时改变了既有用户的**权利主张**（P₀ vs 0）与**可用量上限**（P₀ vs gap）。
所以 Δ(Q0/Q1 × Ld/Ls) 里除了"水质 × 优先级"的交互，还混进了"池容量对既有用户的开放度"。
作为 2×2 因子设计，**L 这一维不是单一因子**。需要拆成 L-claim 与 L-capacity 两个因子，
或固定其中一个。

### B5. 单日代表 + 年度缩放，丢掉了季节与极端高温

T2/T9 都用"湿球中位日"跑 `calculate_data_center_plan`，再用 `E_total` 缩放成 730 天。
但：

- 冷却塔的**补水需求、CoC、水质约束在高温高湿季最紧**；
- 用水质约束做全年判断，必须看**最不利时段**，中位日必然低估约束。

预注册的指标 C（热浪期高峰能力，明令"不得用年均值替代"）因此无法由这套方法支撑。
这是 T5 未做的直接后果，但在 T9 的"可迁移性"结论里已被当作已解决。

### B6. 代码与文档的估计量定义不一致（stale docstring）

`T2_joint_quality_allocation.py` 头注释写
`S_city = (M0 − M) − displacement, displacement = max(0, x_ai − dP)`，
实际代码是 `s_city = s_ai + inc_recl − p0`。两者在 ΔP > 0 时不等价。文档必须改。

### B7. 违反自己预注册的 η 记账纪律

预注册 §3：`η_transfer = S_city/S_AI`，且"S_AI ≤ 0 ⇒ 记 NA"。
但 T2/T9 的条件是 `abs(s_ai) > 1e-9`，**负的 S_AI 仍会报出 η**。需按预注册改为
`S_AI > 0` 才报 η。

## C 级：数据质量问题

### C1. Figshare 两个水样的 TDS 是估算值，且阴离子缺失

```python
comp["TDS"] = 0.65 * ec     # EC(µS/cm) → TDS(mg/L) 的经验系数
```

RW（TDS 1378）与 BW（TDS 6131）的 TDS **不是实测**，是 EC×0.65 的换算；两样的
chloride / alkalinity / silica 全缺，BW 的阴离子（Cl⁻、SO₄²⁻）未记录 →
**电荷平衡无法核验**（Na⁺ 2000 mg/L ≈ 87 meq/L，却有 ~90 meq/L 阳离子无对应阴离子）。
这两条数据目前不足以支撑"高盐/微咸"的水化学结论。

### C2. 苦咸水不是"再生水"

"Figshare BW"是**微咸水/苦咸水（brackish water，标签 5 g·L⁻¹）**，属海水淡化或地下苦咸水范畴，
不是市政再生水。把它计入"再生水水质跨度 200×"会把一个**不同水源类别**混进分布，
审稿人会直接质疑抽样效度。建议：或剔除，或明确标为"非再生水边界情形"。

### C3. Meta WUE 数据有 14/90 缺失、2 个 0 值、若干明显不完整记录

```
n = 90，有效 76；NaN 14；wue = 0 的记录 2 条
DeKalb_IL 2021:  4 724 MWh, 0.0 ML   ← 数据中心年电量数千 MWh 明显不完整
Gallatin_TN 2022: 6 264 MWh, 0.0 ML
Gallatin_TN 2021: 0.0 MWh
```

且 `observed_wue_min = 0.0`，于是 `model_inside_observed_envelope = True` 是**平凡成立**
（任何正数都落在 [0, 2.31] 内）。这个"锚定"没有信息量。应改用 IQR、剔除 0/缺失、
并说明各 facility-year 的披露口径。

### C4. WUE 比较两端口径不对齐

- 分子：模型 = **冷却补水**（不含园区生活/灌溉）；Meta = **园区总取水**；
- 分母：模型 = **IT 电量**；Meta = **园区总电量**（含制冷、配电损耗，PUE>1）。

两个偏差方向相反，所以"模型高于 Meta 中位 9.6×"不能直接解读。要么把模型补到园区口径，
要么把 Meta 折算到 IT 口径。

### C5. GSA「独立实测确认」被高估

- 对象是**美国法院冷却塔**（102 天，分 3 段），不是数据中心；
- `M/E` 与 `CoC/(CoC−1)` 的关系在**给定 CoC**时是代数恒等式（`CoC = M/(M−E)`）；
- 报告自己的 `coc_from_form`（2.8146）与 `coc_water_balance`（2.8）几乎相等，
  说明检验的其实是"原报告自身水量账自洽"，而非在数据中心上验证了物理律。

结论应降级为"原报告水量账算术自洽"，而不是"中心物理关系被独立实测确认"。

### C6. 模型内部 CoC 不一致未如实呈现

T7 产物自己给出：`CoC_design = 5.00` 但 `CoC_implied_by_M_over_E = 5.4439`。
原因是内部回收（10%）抬高了有效浓缩倍数（M − E = 5 132.7 = 排污 5 703.0 × 0.9）。
报告写成"模型设计 CoC=5.00 **恰好略高于** GSA 实测包络 [2.80, 4.91]"，但**实际有效值 5.44**
明显在包络之外。需统一"设计 CoC"与"实际 CoC"的口径并如实陈述。

## D 级：更深的原理性问题（决定论文能不能成立）

### D1. 核心"零传递"结论是会计规则的产物，不是物理定律 ★

R9 实测（D-HA）：

| f | AI 自来水 | 其他用户自来水 | 合计 |
|---:|---:|---:|---:|
| 0.0 | 27 973.5 | 157 849.1 | 185 822.6 |
| 0.3 | 19 581.4 | 166 241.1 | 185 822.5 |
| 0.5 | 13 986.7 | 171 835.8 | 185 822.5 |

其他用户自来水**逐点 1:1 精确跟随** AI 的再生水取用（Δ 差 < 0.2 ML）。
这就是"零传递"的全部来源：**模型假设既有用户的用水需求完全刚性，缺多少就用自来水补多少**。

- 作为**条件命题**它是成立的、且有政策价值（"若既有用户服务刚性且再生水总量固定，
  则 AI 取用是零和"）；
- 但它**不是**"发现了一个反直觉的城市水代谢规律"。现实中既有用户可能压减需求、
  改用其他水源、或按合同让渡——这些都被假设掉了。

**主张必须写成条件命题**，并在论文里把"既有用户需求弹性"作为显式参数（T1b 的 ω 已经在做这件事）。

### D2. S_AI 只是"自来水取水"的节约；AI 总取水量在 φ ≤ 0.55 完全不变

R9 里 `ai_withdrawal_ml` 在 f ∈ [0, 0.5] 恒为 27 973.5。所谓"设施级节水"实为
**取水源的替换**，不是用水量的下降。报告多处写"设施级节水"，容易被读成"数据中心少用水"，
这会误导审稿人。应全程统一为"AI 自来水取水（W_AI,pot）"。

### D3. 苦咸水结果由发散量驱动，不应作为数字呈现

`M = E·CoC/(CoC−1)` 在 CoC→1 时发散。苦咸水掺混下 CoC → 1.0–1.1，于是
`Δ|Ld = −66 650`、`Δ|Ls = −106 961`、`Δ_QL = +40 311 ML` 都是**趋近发散的差值**，
量级取决于网格截断，不是物理成本。报告已注明"结构性不可行"，但把这些数字
写进核心结果表（§1.4c）会让人误以为它们可解释。应改为"不可行域"定性呈现。

### D4. 指标 B（流域净耗水）与 C（高峰能力）完全没做，但话语已经越界

预注册 §1 明令三项不可合并、B 需流域水文数据、C 不得用年均值替代，
并且"不得由 A 直接推断 B/C"。但阶段报告与结论里已经出现"城市水安全"、
"城市级水资源收益"等表述。目前的证据只支持**指标 A（城市水源取水）**。
在 B/C 完成前，全文用词必须锁死在 A。

### D5. δ 的定义域与"E 无关"的表述

- T9 的 δ = 1 − (pool − inc_recl)/x_ai 中，pool 在抽样里被缩放到 [0.3, 4.0]×P₀，
  所以 δ 里已经含着"城市规模/池规模"。报告说"E 消去、y 与城市规模无关"，
  实际是**把 E 搬进了 δ**——δ 与外生城市参数不是独立的。
- δ 允许 > 1（可到 3 以上），语义是"新增供给超过 AI 再生水需求"。报告 §6.2 已提到
  "须明确定义域"，但阈值表 δ\* 最大到 2.855，仍与 δ 的物理上界混在一起。

5. **T1 的通用收支闭合（1.8e-12 ML）与跨模块一致性（3.6e-12 ML）**是真检验，

## 对论文主张的影响

**当前主张**（T9 §7）：
> 城市级水资源收益可折叠到两个无量纲群 w 与 Φ；收益为正判据 δ > δ\*(φ)……

**审计后应收紧为**：

> **在"既有用水户服务刚性 + 再生水总量固定"的会计条件下**，AI 数据中心取用再生水
> 对城市水源取水（指标 A）是**零和的**：设施级自来水替代不产生城市级节约；
> 城市能否获益，取决于新增回用能力带来的**净新增供水** δ 是否超过水质惩罚阈值 δ\*(φ)，
> 而 δ 的归属由**用水权认定规则**决定。
> 该结论目前基于 2 个同源合成城区与 5 组公开水样（其中 2 组 TDS 为估算、1 组非再生水），
> **指标 B/C 未评估**。
