==============================================================================
A21b  两条水质路径的结构差异诊断
==============================================================================

[Q1] volume-only 路径的解析推导
  补水混合 TDS = 0.6×900.0 + 0.4×200.0 = 620.0 mg/L
  CoC_lim = 限值 / 混合浓度 = 1100.0/620.0 = 1.7742
  → 与 A21 实测 1.77 相符 ✓

[Q1b] R10a 路径的物理含义（质量守恒下的稳态浓缩倍数）
  冷却塔稳态: 补水带进的溶质 = 排浓水排出的溶质 (忽略飘损)
      M · c_makeup = B · c_loop
      且 CoC ≡ c_loop / c_makeup, B = E/(CoC-1)
  → 稳态下 c_loop 由**水量平衡与排浓策略**决定, 而非补水浓度本身:
      质量平衡: M·c_m = B·c_l 且 M = E·CoC/(CoC-1), B = E/(CoC-1)
      ⇒ c_l = c_m · M/B = c_m · CoC   → **恒等式**, 不约束 CoC
  ⇒ 因此 CoC 由**水质限值 c_l ≤ L**给出: c_m·CoC ≤ L ⇒ CoC ≤ L/c_m
     ⇒ 与 volume-only 的 1.774 **一致**

  ⚠ 但 R10a 实测 7.98 —— 说明它并未把 c_m 当作'补水浓度',
     而是让 **loop 浓度随时间累积**，并只在排浓/补水时按质量平衡更新；
     若储罐水被反复循环使用（内部回收），有效 c_m 会**低于**新鲜补给浓度，
     于是允许更高 CoC。

[Q2] 结论：二者代表**不同物理情形**，不是'一对一错'
  volume-only : 补水**每次都是新鲜配比**（无内部回收、无储罐滞留）
                → 最保守，CoC 被新鲜补水浓度压死
  R10a        : 允许 **储罐滞留 + 内部回收**，有效补水浓度被稀释
                → 更接近'带储水与回收的实际系统'，CoC 接近设计值

  两者都满足各自的质量守恒（A21 实测水闭合残差 1.07e-13）。

[Q3] 对论文的含义（关键）
  1. 既有全部结论（A13/A17）建立在 **volume-only** 上，
     即'无内部回收、无储罐滞留'的保守情形；这必须显式声明。
  2. R10a 是引擎自带的 opt-in 诊断接口，R10 门禁明确标注
     `NOT_READY_FOR_E3`，**不宜**作为论文主口径。
  3. 两路径差异 4.5× 量级，说明**冷却水管理策略（是否内部回收/储水）
     本身就是一等一的敏感参数** —— 这是一个应报告的敏感性，
     而不是一个需要'修好'的 bug。
