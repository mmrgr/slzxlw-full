# 自我验证清单 — Verification Checklist

> **用途**：在 AI Coding Agent 输出关键结论后，要求其回答以下清单中的问题。flash 模型不擅长"自我检查"，但擅长"回答具体问题"。把开放式检查变成具体问答，可以显著提高验证质量。

---

## 使用方式

1. 在关键阶段输出后，选择对应的验证清单
2. 要求 Agent **逐条回答**，每条回答必须明确给出"通过"或"未通过"
3. 任何"未通过"的条目，触发迭代深化（最多2轮）
4. 所有条目通过后，才允许进入下一阶段

      □ 通过  □ 未通过 → [说明缺失维度]

V1.4 是否枚举了至少3个边缘情况？
      □ 通过  □ 未通过 → [说明缺失的边缘情况]

      □ 通过  □ 未通过 → [说明未覆盖的P0需求]

      □ 通过  □ 未通过 → [说明不可验证的标准]

## 清单2: 架构验证清单

**适用阶段**：Phase 2 完成后

```
V2.1 是否至少设计了2个有实质性差异的方案？
      □ 通过  □ 未通过 → [说明方案差异不足]

V2.2 方案比较是否基于具体维度（Token/并行度/容错/可维护性）？
      □ 通过  □ 未通过 → [说明缺失的比较维度]

V2.3 选择理由是否引用了比较结果？不是凭直觉？
      □ 通过  □ 未通过 → [说明直觉决策]

      □ 没有职责高度重叠的Agent

V2.5 是否考虑了失败模式？如果主方案失败，有没有降级策略？
      □ 通过  □ 未通过 → [说明缺失的降级策略]

V2.6 Agent数量是否在预算范围内？（max_agents）
      □ 通过  □ 未通过 → [说明超预算]

V2.7 反事实思考：假设这个架构决策是错的，最可能错在哪里？
      回答：[具体回答]
      基于回答是否需要修改：□ 不需要  □ 需要 → [修改说明]
```

## 清单5: 集成验证清单

**适用阶段**：Phase 7 完成后

```
V5.1 结构完整性：
      □ DAG中所有任务都有对应Agent定义
      □ 所有Agent都在DAG中出现
      □ 没有悬空任务
      全部满足 → 通过

V5.2 数据流连贯性：
      □ 沿DAG走一遍，每个Agent输入可从前序输出获得
      □ 数据格式匹配
      □ 没有"断流"
      全部满足 → 通过

V5.3 并行安全性：
      □ 同组并行任务不写同一文件
      □ 无循环依赖
      □ 共享资源访问有序
      全部满足 → 通过

V5.4 异常传播：
      □ Agent失败后下游有处理策略
      □ 失败不会被静默吞掉
      □ 有降级策略
      全部满足 → 通过

V5.5 验收标准可验证性：
      □ 每条验收标准都有检查方法
      □ 检查方法可执行
      □ 没有无法验证的标准
      全部满足 → 通过

V5.6 全局一致性：
      □ 指令风格统一
      □ 配置参数不冲突
      □ Agent约束与系统约束不矛盾
      全部满足 → 通过

V5.7 Dry-Run验证：
      □ 所有Agent成功的场景下，输出完整
      □ 某Agent失败的场景下，系统可部分交付
      □ 输入异常的场景下，系统有合理反应
      全部满足 → 通过

V5.8 可追溯性：
      □ 最终结果可追溯到源输入
      □ 可追溯是哪个Agent、哪版指令生成的
      □ 可追溯使用了哪些记忆
      全部满足 → 通过
```

## 通用验证清单（任何阶段都适用）

```
G1. 这个结论/输出的推理过程是否完整？是否有跳步？
G2. 是否考虑了至少一个替代方案？
G3. 是否考虑了边缘情况？
G4. 结论是否与前面的约束一致？
G5. 如果这个结论是错的，最可能错在哪里？
G6. 这个结论是否可以更简单？（奥卡姆剃刀）
G7. 这个结论是否可以验证？如何验证？
```

## 验证结果处理

| 验证结果 | 处理方式 |
|----------|----------|
| 全部通过 | 进入下一阶段 |
| 1-2项未通过 | 迭代深化：针对未通过项重新推理（最多2轮） |
| 3项以上未通过 | 可能是整体方向问题，回到当前阶段开头重新执行 |
| 迭代2轮后仍未通过 | 标记"需人工审查"，输出当前最佳结果，记录未解决项 |

```json
{
  "verification_result": {
    "checklist": "architecture",
    "total_items": 7,
    "passed": 6,
    "failed": 1,
    "failed_items": ["V2.5"],
    "iteration": 1,
    "action": "iterate",
    "notes": "V2.5未通过：缺少主方案失败时的降级策略。需要在迭代中补充。"
  }
}
```
