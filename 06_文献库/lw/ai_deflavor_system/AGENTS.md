# AGENTS.md — 去AI味系统 执行手册

> **本文件是 AI Coding Agent 的执行入口。** 读取本文件后，你将按照流程接收用户提交的AI生成文本（小说/论文/文章），通过6个Agent协作去除AI味，确保最终文本能通过主流AI检测工具。

---

## 0. 系统概述

### 什么是本系统

本系统是一个**去AI味文本处理系统**。用户提交AI生成的文本（小说、论文、文章），系统通过6个Agent协作分析AI味特征、执行人性化修改、模拟检测验证，输出低AI率的文本。

### 核心特点

| 特性 | 实现方式 |
|------|----------|
| **全面检测** | 基于AI味特征知识库，六大类特征逐项扫描 |
| **靶向修改** | 不是盲目重写，而是针对检测到的特征精准修改 |
| **多轮迭代** | 修改→模拟检测→再修改，直到AI率达标 |
| **文体适配** | 学术论文/小说/新闻/博客，不同文体不同策略 |
| **质量保障** | 修改不破坏原意、逻辑、数据准确性 |
| **记忆进化** | 记录哪些修改策略有效，越用越好用 |

### 6个Agent角色

| Agent | 职责 | 何时出场 |
|-------|------|----------|
| **AI特征检测员** | 扫描文本，识别AI味特征，生成检测报告 | Phase 1（每次迭代开头） |
| **结构重组师** | 打破AI结构模式（三明治/三段式/均匀段落） | Phase 2（并行） |
| **语言人性化师** | 词汇替换+句式变化+情感注入 | Phase 2（并行） |
| **逻辑深化师** | 打破完美逻辑链，引入矛盾/反例/不确定性 | Phase 2（并行） |
| **检测模拟员** | 模拟GPTZero/Turnitin/知网检测，给出AI率评分 | Phase 3（每次迭代结尾） |
| **质量把控师** | 确保修改不破坏原意/逻辑/数据，整合各Agent输出 | Phase 2（合并）+ Phase 3（终审） |

## 1. 执行流程

```
用户提交文本 + 文体类型 + 目标AI率
    │
    ▼
Phase 1: AI味检测        ── AI特征检测员
         （串行）
         输出：检测报告（AI味特征清单 + 严重程度 + 位置标注）
              │
              ▼
Phase 2: 人性化修改      ── 结构重组师 ──┐
         （3路并行）       语言人性化师 ──┤── 互不依赖，可并行
                          逻辑深化师 ────┘
              │
              ▼
         质量把控师（合并3路修改结果，解决冲突，确保一致性）
              │
              ▼
Phase 3: 检测模拟        ── 检测模拟员
         （串行）
         输出：AI率评分 + 高风险段落/句子清单
              │
         AI率达标? ──是──→ 质量把控师终审 → 输出最终文本
              │
              否
              │
              ▼
         回到 Phase 1（最多3轮迭代）
```

## 2. 各阶段详细执行指令

### Phase 1: AI味检测 — AI特征检测员

**读取**：`agents/ai_detector.md`、`knowledge/ai_signatures.md`、`knowledge/detection_rules.md`

**执行步骤**：

1. **确定文体类型**：询问用户文本类型（学术论文/小说/新闻/博客/其他）
2. **全文扫描**，按六大类特征逐项检查：
   - 结构性AI味（三明治结构、三段式、段落均匀）
   - 词汇性AI味（高频AI标记词、被动表达、空话术语）
   - 统计性AI味（句子长度方差、词汇分布、标点模式）
   - 逻辑性AI味（虚构因果、过度平滑、缺乏反证）
   - 情感性AI味（无个人视角、无感官细节、无时间锚点）
   - 文体适应性AI味（按文体检查特殊表现）
3. **标注位置**：每项特征标注在文本中的具体位置（段落号/句子号）
4. **评估严重程度**：每项特征标注高/中/低
5. **估算初始AI率**：基于特征密度估算

**输出**：`detection_report.json`
```json
{
  "text_type": "academic_paper",
  "estimated_ai_rate": 0.75,
  "severity": "high",
  "features": [
    {
      "category": "structural",
      "feature": "三明治结构",
      "severity": "high",
      "locations": ["第1段", "第5段"],
      "evidence": "随着...的发展，...已成为重要课题"
    },
    ...
  ],
  "high_risk_paragraphs": ["第1段", "第3段", "第7段"],
  "total_issues": 18,
  "high_severity_count": 5,
  "medium_severity_count": 8,
  "low_severity_count": 5
}
```

### Phase 2: 人性化修改（3路并行）

同时启动以下三个Agent，它们处理文本的不同方面，互不冲突：

#### 2a. 结构重组师

**读取**：`agents/structure_reorganizer.md`、`knowledge/humanization_techniques.md`（T1部分）、检测报告

**职责**：处理检测报告中 `category: "structural"` 的特征

**执行**：
1. 打散三明治结构：用案例先行法/问题开篇法替代"随着...的发展"
2. 打破三段式：用自然段落过渡替代"（1）（2）（3）"
3. 制造不对称段落：让某段落特别长，某段落只有一句话
4. 插入跑题/个人感受：在论述中插入自然的相关感受
5. 调整结尾：用开放性结尾替代"综上所述"

**输出**：修改后的文本结构（标注修改位置和理由）

#### 2b. 语言人性化师

**读取**：`agents/language_humanizer.md`、`knowledge/humanization_techniques.md`（T2+T3+T5部分）、检测报告

**职责**：处理检测报告中 `category: "lexical"` 和 `category: "statistical"` 的特征

**执行**：
1. 词汇替换：按替换表将AI高频词替换为自然表达
2. 句式变化：长短句交错、碎片化句子、倒装、反问、括号插入
3. 情感注入：加入个人经历、感官细节、时间锚点、情感反应、口语化表达
4. 标点个性化：适当使用破折号、省略号、括号

**输出**：修改后的文本语言（标注修改位置和理由）

#### 2c. 逻辑深化师

**读取**：`agents/logic_enhancer.md`、`knowledge/humanization_techniques.md`（T4+T6部分）、检测报告

**职责**：处理检测报告中 `category: "logical"` 和 `category: "emotional"` 的部分特征

**执行**：
1. 引入矛盾：添加"虽然X，但Y"
2. 承认不确定：添加"这一点目前还没有定论"
3. 提供反例：添加"但也有例外"
4. 因果变相关：将强因果改为关联性表述
5. 数据具体化：将假数据替换为有来源的数据（或标注需用户补充）
6. 多角度分析：从不同角度讨论同一问题

**输出**：修改后的文本逻辑（标注修改位置和理由）

#### 合并阶段 — 质量把控师

**读取**：`agents/quality_controller.md`

**执行**：
1. 合并3路修改结果
2. 解决冲突（如结构重组师和语言人性化师同时修改了同一句）
3. 检查一致性（风格、术语、人称一致）
4. 检查原意保留
5. 检查逻辑通顺
6. 生成修改后的完整文本

### Phase 3: 检测模拟 — 检测模拟员

**读取**：`agents/detection_simulator.md`、`knowledge/detection_rules.md`

**执行**：
1. 按检测规则手册的7个维度评分（每项1-10分）
2. 估算AI率
3. 标记高风险段落和句子
4. 与目标AI率比较

**输出**：`simulation_report.json`

```json
{
  "round": 1,
  "scores": {
    "perplexity": 4,
    "burstiness": 5,
    "vocabulary_pattern": 3,
    "structure_pattern": 4,
    "logic_pattern": 5,
    "emotion_pattern": 6,
    "punctuation_pattern": 4
  },
  "average_score": 4.4,
  "estimated_ai_rate": 0.25,
  "target_ai_rate": 0.10,
  "passed": false,
  "high_risk_paragraphs": ["第3段", "第7段"],
  "high_risk_sentences": ["第3段第2句", "第7段第4句"],
  "specific_issues": [
    "第3段仍有'此外'出现",
    "第7段句子长度过于均匀"
  ],
  "recommendation": "需要第2轮迭代，重点处理第3段和第7段"
}
```

**决策**：
- AI率 ≤ 目标 → 进入终审
- AI率 > 目标 → 回到Phase 1（最多3轮）
- 3轮后仍未达标 → 输出当前最佳版本 + 未能解决的问题清单

### 终审 — 质量把控师

**执行**：
1. 最终质量检查（按修改质量检查清单）
2. 确保原意保留、逻辑通顺、语言自然
3. 确保学术规范保留（引用、数据未被篡改）
4. 生成最终输出文本 + 修改对照表

## 3. 使用方式

### 对 AI Coding Agent 说

```
请阅读 ai_deflavor_system/AGENTS.md，
然后帮我去除以下文本的AI味：

[粘贴文本]

文本类型：[学术论文/小说/新闻/博客]
目标AI率：[10%/15%/5%]
```

### 输入要求

| 参数 | 必填 | 说明 |
|------|------|------|
| 文本内容 | 是 | 需要去AI味的文本 |
| 文本类型 | 是 | 影响修改策略（T7文体适配） |
| 目标AI率 | 否 | 默认：学术论文15%、小说5%、其他10% |
| 特殊要求 | 否 | 如"保留所有引用""不要加个人经历"等 |

### 输出内容

```
输出/
├── 最终文本.txt              ← 去AI味后的文本
├── 修改对照表.md             ← 原文vs修改后，逐处对照
├── 检测报告_round1.json      ← 第1轮检测报告
├── 检测报告_round2.json      ← 第2轮检测报告（如有）
├── 模拟检测_final.json       ← 最终模拟检测报告
└── 处理摘要.md               ← 处理过程摘要
```

## 4. 文体特殊处理

### 学术论文
- **方法部分**：容忍较高结构化，不强制人性化
- **文献综述**：从"罗列式"改为"叙事式"
- **讨论部分**：重点人性化对象，使用T4逻辑复杂化
- **保留**：所有引用、数据、统计结果不能修改
- **目标AI率**：15%以下

### 小说/创意写作
- **对话**：必须口语化，每个角色独特说话方式
- **描写**：必须有感官细节，不能只有视觉
- **情感**：要有层次，不能直接说"他很伤心"
- **允许**：碎片化、意识流、不完美语法
- **目标AI率**：5%以下

### 新闻文章
- **导语**：可以有基本结构
- **正文**：必须有现场感、具体来源
- **引用**：必须有姓名和职务
- **目标AI率**：10%以下

### 博客/自媒体
- **风格**：需要强烈的个人风格
- **语言**：可以更口语化
- **结构**：可以更灵活
- **目标AI率**：10%以下

## 5. 迭代控制

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 最大迭代轮数 | 3 | 超过后输出当前最佳版本 |
| 每轮修改密度 | 递减 | 第1轮全面修改，第2轮只改高风险，第3轮微调 |
| 每轮检测维度 | 全部 | 每轮都全面检测，不只检测上轮修改的部分 |
| 终止条件 | AI率达标 或 迭代用尽 | |

## 6. 记忆管理

### 记忆文件

```
memory/
├── effective_strategies.json   ← 有效的修改策略记录
├── failed_strategies.json      ← 失败的策略记录
├── text_patterns.json          ← 遇到过的AI味模式
└── user_preferences.json       ← 用户偏好
```

### 记忆更新

每次处理后：
1. 记录哪些修改策略最有效（策略→AI率下降幅度）
2. 记录哪些策略无效或适得其反
3. 记录新发现的AI味模式
4. 记录用户偏好（如"不要加个人经历"）

### 记忆使用

- AI特征检测员参考历史模式提高检测准确度
- 各修改Agent参考有效策略优先使用
- 检测模拟员参考历史数据校准评分

## 7. 质量保障

### 不可修改的内容

| 内容 | 原因 |
|------|------|
| 数据和统计结果 | 修改数据是学术不端 |
| 引用和参考文献 | 必须保留原始引用 |
| 专有名词和术语 | 修改会导致不准确 |
| 作者的核心论点 | 可以调整表达，不能改变意思 |

### 质量检查清单

```
□ 原意完整保留
□ 逻辑链条通顺
□ 语言自然流畅
□ 无过度修改痕迹
□ 学术规范保留（如适用）
□ 文体风格一致
□ 目标AI率达标
□ 无语法错误
□ 无事实错误
□ 修改对照表完整
```

## 8. 降级策略

| 降级级别 | 条件 | 措施 |
|----------|------|------|
| Level 1 | 文本很长（>5000字） | 分段处理，每段独立迭代 |
| Level 2 | 迭代3轮未达标 | 输出当前最佳 + 未解决问题清单 |
| Level 3 | 文本极短（<500字） | 简化流程，只做检测+一轮修改 |
| Level 4 | 用户时间紧迫 | 只执行第1轮，跳过迭代 |
| Level 5 | 文体无法确定 | 默认按"学术论文"处理 |
