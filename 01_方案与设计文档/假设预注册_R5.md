# AI-UWM 瓶颈迁移机制：假设预注册（R5）

**预注册日期**：2026-09-27
**性质**：**事先登録式**（在投稿前登记假设、证据要求与失效条件，防止事后挑选结果）
**上位文件**：`主论点与论证地图_R5.md`、`外部建议评审_2026-09-27.md`
**适用范围**：仅 D-HA / D-CO 两个**合成参数域端点**内部。所有结论形式为「约束结构与迁移」，不含任何真实城市的绝对容量。

---

## 零、为什么需要预注册

外部建议 6 指出："每条机制主张都要有独立证据链、否证条件和重复运行，**不得仅依据单次扫描或字典序瓶颈判定**"。

**已核实：本项目的这一批评成立。** `scripts/diag_constraint_binding.py` 经检查**不含任何随机源**（无 `seed` / `repeat` / `replicates` 参数），瓶颈判定为**确定性单次扫描**。这意味着：

- 主导约束的判定**没有抽样误差估计**；
- "字典序"（同容量点上多个约束同时接近阈值时取哪一个）**未做敏感性检验**。

因此本文档在登记三条机制假设的同时，**如实标注"重复运行尚未实现"**，并给出实现所需的最低种子数。**不把未做的事伪装成已做。**

## 一、三条可否证假设

### H-M1｜约束随容量迁移

> **假设**：在给定端点上，随 AI 容量上升，主导约束（首先失效者）会**发生变更**；迁移路径由该端点的水源侧余量结构决定，而非由设施规模绝对值决定。

| 要素 | 内容 |
|---|---|
| **预测** | 容量扫描中存在至少一个容量点，其主导约束与相邻点不同 |
| **反事实检验** | 若改变某约束的余量（如放宽诉求），迁移点应随之移动；若迁移点不变，则该约束不参与迁移 |
| **负对照** | 容量极低时（如 50 MW）应无任何约束接近阈值——若低容量即已绑定，则扫描基线本身有偏 |
| **跨端点复核** | HA 与 CO 的迁移路径应不同（这是假设的一部分，不是独立假设） |
| **否证条件** | 扫描范围内**所有容量点主导约束相同**，或迁移点随意跳动、不构成单调路径 |
| **当前状态** | ✅ 已有 `constraint_binding_diagnosis.csv`；⚠️ **无重复运行** |

### H-M2｜对症干预有效、非对症干预失效

> **假设**：只有针对某个端点**当前瓶颈环节**的干预才产生 CAWCC 增益；针对非瓶颈环节的干预增益为零，且两者在 HA / CO 之间**互斥**。

| 要素 | 内容 |
|---|---|
| **预测** | HA 仅降漏损类干预有效；CO 仅扩接网类干预有效；其余干预增益为 0 |
| **反事实检验** | 把 HA 的对症干预施加到 CO 应失去增益（端点交叉施用） |
| **负对照** | "零增益但仍有投资"类干预——必须报告其投资额，用以说明"零增益 ≠ 无成本" |
| **否证条件** | 若对症与非对症干预的增益**在不确定性范围内不可区分**，则该区分不成立 |
| **基线要求** | 增益数字**必须注明基线口径**（HA 存在 1100→1300 与 1150→1300 两种口径） |
| **当前状态** | ✅ 已检验 10 项干预 + 基线对照（`intervention_baseline_alignment.csv`）；⚠️ 无抽样重复 |

---

### H-M3｜库容边界与吞吐边界的关系是**端点依赖**的

> **假设（原表述已被部分否证，此处登记修正后版本）**：设施吞吐边界（E1）与库容可持续边界（E3/E4）之间的比值**取决于端点**。在 HA 端点二者相差约 6 倍；在 CO 端点二者同量级。

| 要素 | 内容 |
|---|---|
| **原假设** | "库容边界 ≪ 吞吐边界（差一个量级）"——**两域普遍成立** |
| **检验结果（T0.4，已执行）** | HA 比值中位 **5.75**（12/12 ≥3）→ 成立，但应降调为"约 6 倍"而非"一个量级"<br>CO 比值中位 **1.61**（0/12 ≥3）→ **原表述在 CO 端点被否证** |
| **修正后假设** | 该换算警示**只在缺水端（HA）成立**；CO 端点须写成边界条件 |
| **负结果的处理** | ★ CO 的同量级结果作为**正式边界条件**保留并进入正文，**不隐藏为异常值**——这是 T0.4 的科学产出，不是缺陷 |
| **跨端点复核** | 已天然完成（本假设本身即跨端点比较） |
| **否证条件** | 若多序列集合中比值中位数 < 3，"差一个量级"失效（HA 未触发，CO 已触发） |
| **当前状态** | ✅ 已检验并完成修正 |

## 二、尚未满足的证据要求（如实登记）

| 要求 | 状态 | 阻塞原因 | 解除条件 |
|---|---|---|---|
| **瓶颈判定的重复运行** | ❌ 未实现 | `diag_constraint_binding.py` 无随机源 | 需在容量扫描中加入 ≥3 个驱动种子，报告每个容量点上主导约束的**一致性频率**（例如"24/24 次 Notes 为 X") |
| 字典序敏感性检验 | ❌ 未实现 | 同上 | 在约束接近阈值的点附近做 ±2% 阈值扰动，检查主导约束是否翻转 |
| 20 条以上水文序列 | 🔄 进行中（12→20） | 计算成本 | 本轮正在补；但**注意**序列仍来自同一合成驱动规则，`hydrology_validation = NONE` |
| 真实数据外部复现 | ❌ 不可执行 | E1 闸门关闭 | 见 `外部证据闸门记录_R5.md` |

> **关于"20 条序列"的辩证立场**：补充序列条数可以提高采样精度，但**不会提高证据等级**——这些序列是同一个（未经观测验证的）驱动规则的不同种子抽样。它检验的是"端点规则下的采样稳定性"，不能外推为"水文不确定性已被表征"。

5. 任何"耐久性报告"都必须携带 `hydrology_validation` 状态标签。
