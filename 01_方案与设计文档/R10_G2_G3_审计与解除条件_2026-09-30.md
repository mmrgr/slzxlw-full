# R10 G2/G3 证据审计与解除条件（2026-09-30）

## 1. 审计目的与结论

本文件只审计 G2（化学交叉验证）和 G3（设施行为留出验证）。它不把模型内部守恒、文献量级或合成序列升级为外部观测证据，也不改变主模型代码。

**当前结论：G2 = `NOT_READY`，G3 = `NOT_READY`。** 这个状态必须保留在 R10 注册表和 E3/E4 运行控制中。

审计依据：

- `scripts/audit_g2_g3_evidence.py` 的只读库存检查（本文件同批新增）；
- `validation_artifacts/r2/reclaimed_compatibility_gate_R9.json`；
- `data/parameter_registry.csv`、`data/scenario_registry.csv`；
- `08_实验数据/README_数据说明.md` 与 `README_导出索引_自动生成.md`；
- `01_方案与设计文档/外部证据闸门记录_R5.md`。

库存检查的关键结果为：已增加一个 129 样本的 Water Quality Portal 环境水化学 pilot 及其 IPhreeqc `PILOT_ONLY` 输出；同一批样本现在带有直接 TDS（WQP 70300）和氯化物的条件 reduced-order 对照，输出逐样本限制指标、排序、CoC 差值以及条件 false-safe/false-unsafe 统计。该对照仍是环境水筛查，未完成再生水来源审查、化学判据人工复核或完整 `PASS` manifest；唯一被文件名标为 `observed.csv` 的示例来自 `examples/demo_full/create_demo_inputs.py` 的模型输出加噪声，属于合成伪观测，已排除；16 条 R10 情景注册表记录全部为 `not_ready`。

## 2. 现有证据的等级边界

| 证据 | 现有内容 | 可以支持 | 不能支持 |
|---|---|---|---|
| R9 质量固定点 | 单数据中心、1000 MW、零冷却储水、固定 TDS/氯化物点值；`G0_fixed_point=PASS`，`root_count=1`，最大残差约 `9.98e-11` | 数值迭代的收敛、内部水量/状态规则的一致性 | 独立化学模型一致性、现场水质分布、设施预测 |
| R9 联合池 | `G2_shared_pool_joint_solver=NOT_READY` | 明确当前联合池范围的边界 | 多 DC 真实竞争下的化学交叉验证 |
| R10 参数注册表 | 10 行；8 行 `observation_population=scenario_prior`；再生水 TDS/Cl 为情景先验 | 参数来源和证据等级可追溯 | observed-distribution chemistry、校准或验证 |
| R10 情景注册表 | 16 个 `Q×L×A` 组合，全部 `not_ready` | 防止未通过门禁的情景误运行 | 任一 E3/E4 正式结果 |
| R2 导出数据 | 45 个情景、730 日合成驱动及其聚合/抽样过程表 | 机制模型、内部恒等式、参数域敏感性 | 城市或设施的实测预测、G3 留出误差 |
| `examples/demo_full/observed.csv` | 脚本由模型 `outflow_ml` 加随机噪声生成 | 仅可作方法层“能否复原已知合成真值”示例 | 外部观测、设施留出集 |
| 文献/标准锚点 | ASHRAE、LBNL、ISO 等量级或定义 | 约束参数包络、定义测量口径 | 替代本研究设施的校准和独立验证 |

因此，当前 R9/R10 质量结果的证据标签只能是 `scenario_prior` 或 `internal_consistency`；禁止写成 `observed`、`field-calibrated`、`validated chemistry` 或 `facility-predictive`。

## 4. 最小数据协议（未来入库前冻结）

### 4.0 公开候选数据的边界审查

已检查两类公开资料，均只能作为候选输入，不能直接解除 G3：

- NLR/DOE 的 ESIF 数据集提供单个 HPC 设施的高频 PUE、IT 功率、冷却功率、泵功率和室外气象时间序列，但页面未提供与本项目字段一一对应的补水、排污、CoC 和水质表计；
- Google 环境报告按数据中心地点提供年度取水、排水和消耗量，并披露季度/滚动 12 个月 PUE，但不提供逐设施 CoC、补水/排污拆分或可供留一验证的日序列。
- Meta 2025 Environmental Data Index 已保存原始 PDF、18 个命名设施的 2020–2024 年度电量/取水表和哈希 manifest；它补足了公开设施清单与年度量级，但取水口径在缺失时允许代理估算，且没有日级时间戳、表计、补水/排污/CoC 或留出预测 provenance，因此仍只能登记为 `E2_public_annual_disclosure`。

因此这些资料可用于量级和字段定义审查，不能被插值或反推成 G3 观测。来源：[NLR HPC PUE 数据集](https://data.nlr.gov/submissions/300)；[Google 2025 Environmental Report](https://sustainability.google/reports/google-2025-environmental-report/)。

### 4.1 G2 独立化学包

建议目录：`data/external_validation/g2_phreeqc/`。每一批数据须同时保存原始文件、清洗映射和哈希。

`water_samples.csv` 至少包含：

- `sample_id, source_stage, facility_or_plant_id, collection_time, timezone`；
- `tds_mg_l, chloride_mg_l, ph, temperature_c, conductivity`；
- `calcium, magnesium, sodium, potassium, bicarbonate, carbonate, sulfate, nitrate, silica` 及各自单位、检测限和不确定度；
- `treatment_stage`（原水、二级出水、再生水、混合水等）、采样/实验室、方法、证据类型和可追溯来源。

每个样本还要有：

1. PHREEQC 版本、数据库文件名与哈希、输入文件和输出日志；
2. reduced-order 输入的同一组浓度、温度和边界条件；
3. `limiting_species, max_safe_coc, reduced_order_coc, phreeqc_coc, coc_delta, safe_unsafe_label`；
4. 预先定义的危险水样排序和 false-safe/false-unsafe 计数。

只有“独立求解器 + 可追溯样本 + 逐样本输出”三者齐全，G2 才能审计。只增加 TDS/氯化物点值或文献范围不解除 G2。

### 4.2 G3 设施留出包

建议目录：`data/external_validation/g3_facility_holdout/`。最小可用设计为 **至少 3 个独立 facility/study 单元，每个至少 12 个月**；少于 3 个只能标为探索性方法验证，不能称 G3 PASS。

`facility_daily.csv`（或保留原始更高频表计并提供日聚合）至少包含：

- `facility_id, study_id, date, timezone, source_uri, meter_id`；
- IT 负荷/电量、设施电量、PUE；
- 冷却补水、排污、漂水、回流、CoC、WUE；
- 干球/湿球温度、冷却技术、再生水比例和关键水质指标；
- 缺失标识、仪器精度/校准日期、聚合方法和时间覆盖率。

拆分规则：按 `facility_id` 或 `study_id` 留一，禁止同一设施的日期、派生变量或调参结果同时进入校准和验证；任何由模型生成的 `synthetic_observed` 只能作为方法测试，不能进入 G3。正式阈值（建议先登记 WUE/补水/排污相对误差、CoC 绝对误差和 ≥90% 覆盖率）必须在查看留出结果前冻结。

## 5. 解锁命令与门禁输出

### 5.1 当前可执行的审计命令

在 `aiuwm_src` 根目录运行：

```powershell
python scripts/audit_g2_g3_evidence.py `
  --repo-root . `
  --experiment-root "C:\Users\mmrgr\Desktop\论文\算力中心\08_实验数据" `
  --json
```

当前输出必须保持：

```text
g2.status = NOT_READY
g3.status = NOT_READY
```

该脚本现在还会核验候选 PASS manifest 所引用的输入/输出文件、SHA-256、行数、样本/设施结构、质量与 provenance 字段、留出训练范围以及独立审阅记录；不再接受只填写 `status=PASS` 的占位 JSON。它仍不把文件名中的 `observed` 视为观测；`examples/demo_full/observed.csv` 已被识别为合成伪观测。

### 5.2 数据到位后的解锁命令（runner 已实现；结果仍须经过独立审阅）

需要先实现并审阅两个独立 runner，命令接口冻结为：

```powershell
python scripts/run_g2_phreeqc_crosscheck.py `
  --samples data/external_validation/g2_phreeqc/water_samples.csv `
  --phreeqc-input data/external_validation/g2_phreeqc/phreeqc_inputs `
  --database data/external_validation/g2_phreeqc/database.dat `
  --output validation_artifacts/g2_phreeqc_crosscheck

python scripts/run_g3_facility_holdout.py `
  --observations data/external_validation/g3_facility_holdout/facility_daily.csv `
  --split leave-one-facility-out `
  --output validation_artifacts/g3_facility_holdout
```

`run_g3_facility_holdout.py` 已作为 stdlib-only gate runner 入库。它要求 `facility_daily.csv` 同时提供设施/研究对象标识、日期与时区、来源 URI、表计 ID、IT/设施电量、PUE、观测 WUE/补水/排污/CoC、对应的 out-of-sample 预测值，以及 `synthetic_observed`、`observed_flag`、`prediction_source`、`prediction_training_facilities` provenance 列。脚本按 facility 留一计算逐设施相对误差/绝对误差、日期覆盖率和日历月数，并将冻结阈值（WUE 20%、补水 20%、排污 25%、CoC 0.5、覆盖率 90%）写入 `manifest.json`。缺列、来源不可追溯、合成标记、训练范围含留出设施、设施少于 3 个、每设施少于 12 个月或覆盖率不足时，状态只能为 `NOT_READY`；完整非合成数据但误差超阈值时为 `FAIL`，不得升级为 `PASS`。

两个 runner 的输出必须包含输入哈希、软件/数据库版本、随机种子（若有）、样本/设施清单、缺失率、逐对象指标和预注册阈值判定。任一 runner 缺失、失败或只产生合成伪观测时，门禁仍为 `NOT_READY`。G3 runner 即使输出 `PASS`，仍需独立审阅其来源、校准/留出隔离和指标口径后，才可将 manifest 作为门禁证据。

已新增 `scripts/run_g2_phreeqc_crosscheck.py` 作为独立求解器 pilot。它通过可选依赖 `phreeqpython==1.6.2` 调用 IPhreeqc `vitens.dat`，输出逐样本 saturation index、限制相和浓缩倍数诊断，并记录输入/数据库哈希。对含直接 TDS（WQP 70300）的样本，脚本还按注册的 TDS/氯化物限值生成条件 reduced-order CoC、限制指标、排序及 false-safe/false-unsafe 统计；这只是线性累积模型与矿物相 SI 判据的条件筛查，不能当作设施安全结论。脚本固定输出 `status=PILOT_ONLY`，不会自动写入 PASS manifest；只有将再生水真实来源、判据人工复核和其余冻结条件补齐后，才可另行生成完整 G2 PASS manifest。

当前已有的 `scripts/run_r10_pilot.py` 只是 gate-safe preflight；它只返回
`DIAGNOSTIC_PREFLIGHT_ONLY`，不会替代上述两个验证 runner，也不会生成正式 E3/E4 数字。

本轮新增外部公开冷却塔处理试验数据的只读登记：`data/external_evidence_registry.csv` 与 `validation_artifacts/external_evidence/aqua_spice_manifest.json`。AquaSPICE 数据可用于 A1/A2 处理参数的来源筛选和冷却塔处理账本核对，但不是数据中心设施留出集，也不包含独立 PHREEQC 交叉输出；登记结果明确保持 G2/G3 `NOT_READY`，不得据此解锁正式 E3/E4。

## 6. 论文表述限制

在 G2/G3 解除前，结果段只能写：

> 在合成驱动和情景先验水质下，模型通过了内部数值闭合与固定点收敛检查；本研究尚未完成独立化学交叉验证或设施留出验证，因此结果用于机制比较，不代表现场预测。

不得写“已验证的再生水化学分布”“现场校准的 WUE/CoC”“对真实设施具有预测精度”，也不得把文献锚点、参数包络或合成伪观测改写成实测。
